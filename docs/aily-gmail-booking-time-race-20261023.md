# Gmail予約同期中の日時変更保護（2026-10-23）

## 今回の最小納品単位

- 対象: HPB／minimo予約メールを既存予約へ同期する処理
- 利用者に増える安全性: スタッフが予約日時を変更した直後に古いメール同期が重なっても、同期を停止し、スタッフが保存した日時を上書きしない
- 操作方法: 従来どおり予約カレンダーのGmail同期を使う。競合時は最新内容を確認してから再試行する
- DB migration、環境変数、認証方式、実メール・LINE送信は変更しない

## 原因と修正

同期は読取時点の予約状態とメモを条件に更新していたが、開始・終了日時を条件に含めていなかった。このため読取後、更新前にスタッフが日時だけを変えると、同期が古い日時を再保存できた。

既存予約の通常更新と、同時登録で決定的IDが競合した後の更新の両方で、読取時点の `start_at` / `end_at` を更新条件へ追加した。更新対象が0件なら再読取し、日時変更を検出して明示的に停止する。DBが同じ時刻を異なるタイムゾーン表記で返しても誤判定しないよう、再読取比較は時刻値で行う。

## 受入条件

1. スタッフが同期中に開始または終了日時を変更した場合、同期はその日時を上書きしない
2. 競合時は「予約日時が変更されました」と表示できるエラーで停止する
3. 既存の状態・メモ競合保護、キャンセル優先、二重登録収束を維持する
4. 競合がないHPB／minimo同期は従来どおり更新・登録できる
