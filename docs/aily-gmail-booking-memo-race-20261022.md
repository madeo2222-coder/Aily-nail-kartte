# Gmail予約同期とスタッフメモの競合保護（2026-10-22）

## 利用者への効果

HPB/minimoの予約受付・変更メールを同期する直前にスタッフが予約メモを追記しても、同期処理が読取済みの古いメモで追記を上書きしない。

## 実装

- 既存予約の更新条件に、読取時点の予約状態だけでなくメモも追加した。
- 更新対象が0件になった場合は予約を再読込する。
- キャンセル済みなら従来どおりキャンセルを優先して収束する。
- 状態が同じままメモだけ変わっていれば、スタッフ追記を保護した旨を返し、同期成功件数へ含めない。
- 同じ予約番号の同時作成後に更新へ収束する経路にも同じメモ条件を適用した。

## 境界

- DB schema、migration、環境変数、Gmail接続、実顧客への通知送信は変更しない。
- 競合時は自動でメモを推測統合しない。予約の最新内容を確認してから同期を再試行する。
- Aily実DB、実Gmail、実スタッフ操作の同時実行は未検証。

## 受入条件

1. 同期処理が既存予約を読んだ後、スタッフが同じ予約のメモを保存する。
2. 古いメモを条件にした同期更新は0件となる。
3. スタッフのメモは残り、同期は成功扱いされず確認案内を返す。
4. 同時にキャンセルされた場合は予約受付メールで再有効化しない。
