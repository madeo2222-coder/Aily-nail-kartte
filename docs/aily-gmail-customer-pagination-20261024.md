# Gmail予約同期の顧客照合ページング（2026-10-24）

## 利用者への変化

HPB／minimo予約メールを顧客カルテへ結び付ける際、同一サロンの顧客がSupabase Data APIの1回あたりの返却上限を超えても、後続ページにいる既存顧客を電話番号・氏名・カナで照合できるようにした。

これにより、顧客数の増加後に既存顧客を見落として予約番号由来の別顧客を自動作成する経路を防ぐ。予約保存、既存の照合優先順位、同名・同電話番号が複数ある場合の扱いは変更しない。

## 実装

- 顧客一覧を `id` 昇順で固定し、0始まり・終端含有の1,000件単位で全ページを読む。
- 途中ページで読取エラーが発生した場合は、取得済みの不完全な一覧で照合せず同期を停止する。
- DB schema、migration、RLS、環境変数は変更しない。

Supabase公式仕様では `select()` の既定最大返却数は1,000件で、`range()` によるページングが案内されている。また `range()` は順序指定がないと結果が不安定になり得るため、`id` の昇順を明示した。
