# HPB / minimo Gmail同期: スレッド不明の取得失敗を安全に保留

## 利用者への影響

Gmailから取得した予約メールのうち、本文取得に失敗し、かつGmailスレッドIDも取得できないメールが1件でもある場合、対象の予約メール全体を今回は書き込まずに保留する。

これにより、取得できなかったメールが新しい日時変更やキャンセルだった場合に、読めた古い予約メールだけを先に反映して予約状態を巻き戻すことを防ぐ。通常どおり本文とスレッドIDを取得できる実行、および失敗したスレッドを特定できる実行では、既存の同期動作を維持する。

## 変更範囲

- `app/api/hpb-gmail-sync/route.ts`
  - 本文取得失敗にスレッドIDがないかを同期前に判定する。
  - 無関係と確認できない対象予約メールはDB書込み前に保留する。
  - HPB / minimo予約メールではないメールは従来どおりスキップする。
- `tests/hpb-gmail-sync-auth.test.mjs`
  - スレッド不明の取得失敗と、別スレッドの読取成功が混在しても予約を書き込まない回帰テストを追加する。

DB migration、RLS、認証設定、環境変数、実顧客へのLINE・メール送信は変更しない。

## 受入条件

1. スレッドIDのないメール本文取得失敗と対象予約メールが混在した場合、HTTP 502かつ同期件数0になる。
2. 取得できた予約メールも保留理由を返し、`syncHpbMailText`を呼ばない。
3. 取得失敗のスレッドを特定でき、別スレッドの予約が成功している既存ケースは部分成功を維持する。
4. 同一スレッド内の取得失敗を保留する既存動作を維持する。
