# Gmail予約同期の顧客紐付け保護（2026-10-23）

## 今回の納品単位

HPB／minimoの予約メールを再処理した際に、スタッフが予約詳細で修正した顧客紐付けを古いメール内容で戻さないようにした。

## 変更内容

- 既存の外部予約にメール照合結果と異なる顧客が紐付いている場合、更新せず同期を停止する。
- 予約の読取後から更新までの間に顧客紐付けが変わった場合、楽観的ロックで更新を止める。
- 同じ外部予約が別処理で先に作成された競合時も、異なる顧客への再紐付けを拒否する。
- 顧客未設定の予約、または同じ顧客に紐付いた予約は従来どおり同期できる。

## 受入条件

1. スタッフ修正済みの顧客紐付けが、メール再処理で変更されない。
2. 同期処理中に顧客紐付けが変わった場合は成功扱いにせず、再確認を促すエラーになる。
3. 同時作成競合でもスタッフ修正済みの顧客を上書きしない。
4. 既存のキャンセル優先、ステータス・メモ・日時の競合保護を維持する。

## 検証範囲

- 顧客紐付けの再処理・同時更新・同時作成競合を自動テストで確認する。
- 全回帰テスト、型検査、lint、ローカル本番ビルドを実施する。
- DB migration、環境変数変更、実メール／LINE送信、実データ更新は行わない。

## 未検証・反映状況

実Supabaseでの書込み、実Gmail同期、実顧客データでの通し確認は未実施。開発統合Previewへの反映前はコード保存済みの確認版であり、現場導入済みとは扱わない。

## 利用者操作

この変更単体で必要な手動DB操作はない。Preview反映後は、通常の予約同期と予約詳細の顧客表示で確認する。
