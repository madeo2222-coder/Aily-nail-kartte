# 顧客予約の古い画面からの変更・取消防止（2026-11-01）

## 利用者が新しくできること

- LINEで開いた予約画面の後にスタッフが予約内容を更新した場合、顧客の古い画面から変更・取消を上書きせず、最新情報の再読み込みを案内する。
- 日時だけでなく、メニュー、担当、予約元、備考を含む表示内容の改訂を確認してから操作する。
- 最新画面からの予約希望変更・取消と、既存の店舗LINE通知は従来どおり利用できる。

## 変更範囲

- 顧客予約詳細APIが返す既存の予約改訂値に、予約元と備考を追加した。
- 顧客画面の直接変更・取消でも、画面に表示した予約改訂値をAPIへ送るようにした。
- APIは改訂値が一致しない操作を、空き枠確認、予約更新、店舗LINE通知より前に停止する。
- DB、migration、認証、環境変数、LINEの送信条件は変更していない。

## 受入条件

- スタッフ更新前の古い画面から変更・取消すると、予約と通知を変更せず再読み込み案内を表示する。
- 最新画面からの変更・取消は既存の競合検査付きRPCへ進む。
- 予約元または備考だけが変わった場合も、古い画面の操作を拒否する。
