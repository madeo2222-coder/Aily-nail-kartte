# 別日時提案LINEの競合・権限エラー表示修正（2026-10-22）

## 目的と範囲

| 項目 | 内容 |
| --- | --- |
| 利用者・目的 | スタッフが別日時入力のLINEを送る直前に予約状態や権限が変わっても、原因不明の500やDB内部文言ではなく次の操作を判断できるようにする |
| 納品範囲 | 既存の別日時提案LINE APIが、送信権の確保RPCから返る既知エラーと予期しないエラーを安全に表示する処理 |
| 受入条件 | 権限・店舗不一致はHTTP 403、予約状態の更新はHTTP 409と再読込案内を返し、未知の内部詳細を応答へ含めず、いずれもLINEを送らない |
| 残件 | 認証済み実データでの申請中予約→別日時提案→顧客入力→スタッフ再表示の通し確認 |
| 予定日 | 次のPreview候補は2026-10-22 20:08:17 JST以降。反映直前に全環境の最新試行から再計算する |
| 必要な本人操作 | 現時点ではなし。実DB・実LINEの確認は、許可されたテスト予約と送信先が確定した後に行う |

## 修正内容

- 送信権を確保する既存RPCの `ALTERNATIVE_REQUEST_INVALID_STAFF` と `ALTERNATIVE_REQUEST_SCOPE_MISMATCH` を、権限案内付きHTTP 403へ変換する。
- `ALTERNATIVE_REQUEST_INVALID_RESERVATION` を、最新状態の再読込を案内するHTTP 409へ変換する。
- 予期しないDB・RPCエラーはサーバーログへ残し、DB関数名や内部詳細をブラウザへ返さない。
- エラー時はLINE APIと送信完了記録を呼び出さない。
- 既存のスタッフ認証、店舗制限、申請中判定、LINE再送キー、送信台帳、再試行条件は変更しない。
- DB、migration、env/secret、実LINE送信は変更しない。
