# HPB／ミニモ予約元の曖昧本文を保存前に停止（2026-10-31）

## 対象

- HPB／ミニモ予約メールの予約元判定
- 転送等で件名から予約元を確定できないメール
- 実DB変更、実LINE／メール送信、環境変数変更、本番公開は含まない

## 問題

転送履歴や貼り付けによって、同じ本文にHPBの構造化された「予約番号」とミニモの「予約ID」が両方入る場合がある。件名にも予約元がなければ、従来は本文中のサービス名から片方を推測していたため、別媒体の予約として解析し、誤った既存予約へ更新する可能性があった。

## 変更

- 件名で予約元が一意に確定できず、HPB予約番号とミニモ予約IDが両方ある場合はDBアクセス前に停止する
- エラーに両方の構造化IDがあることを明示し、スタッフがメール本文を確認できるようにする
- SALON BOARD／HOT PEPPER Beauty／ミニモを明示する正規件名は従来どおり最優先し、本文に別IDが含まれても指定媒体として処理する

## 受入条件

- 一般化した件名と両媒体の構造化IDを持つメールは、顧客検索・予約検索・書込み前に停止する
- HPBを明示する件名では、両方のIDが本文にあってもHPB予約番号を使用する
- 既存のHPB／ミニモ単独メール、キャンセル、遅延同期、重複防止を維持する
- 関連テスト、全回帰テスト、型検査、lint、fixture環境のNext本番buildが成功する
