# 予約確定LINEの安全な再試行表示（2026-10-21）

## 利用者に変わること

- 予約確定LINEの送信結果を確認できない場合、予約一覧・予約編集の両画面で同じ送信を即時に繰り返さない。
- APIが「送信済み」「送信結果不明」「送信記録未保存」「安全な再送期限超過」「予約内容変更」を返した場合、`確定LINEを再試行` を表示せず、送信履歴の確認が必要なことを表示する。
- APIが失敗を送信台帳へ記録し `retryable: true` を返した場合だけ、既存の再試行操作を残す。
- 予約確定の保存結果とLINE通知結果は分けて表示し、LINE結果不明を予約確定失敗として扱わない。

## 実装範囲

- 共通判定 `lib/reservation-confirmation-line-retry.ts` を追加した。
- `app/reservations/ReservationsPageClient.tsx` と `app/reservations/edit/[id]/page.tsx` に同じ判定を適用した。
- 実DB、migration、環境変数、LINE実送信、本番公開は変更していない。

## 検証範囲

- ブラウザがレスポンスを読めない場合の再送停止。
- 送信台帳へ記録済みの再試行可能失敗だけ再送操作を維持。
- 送信済み・結果不明・記録未保存・期限超過・内容変更時の再送停止。
- 両スタッフ画面が共通判定を使用すること。
