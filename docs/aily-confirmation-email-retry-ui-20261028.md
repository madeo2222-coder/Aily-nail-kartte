# 予約確定メールの安全な再試行導線（2026-10-28）

## 利用者ができること

スタッフが予約を確定した直後、メール送信の応答喪失または一時的な送信失敗が起きた場合に限り、予約一覧または予約編集画面へ「確定メールを再試行」を表示する。

予約一覧ではAPIが返した失敗理由と再試行可能時間をボタンと同じ警告枠に残す。スタッフが最初のアラートを閉じた後も、再試行が必要な理由を確認できる。

再試行では既存の予約確定メールAPIを使う。APIは現在の予約・顧客・スタッフ情報を読み直し、同じ内容には同じResend idempotency keyを付けるため、プロバイダーの24時間の保護期間内は重複送信を防ぐ。

## 表示条件

- APIが `retryable: true` を返した場合
- ブラウザがAPI応答を受け取れず、送信結果が不明な場合

送信成功、顧客メール未登録などの送信不要、恒久的な送信エラーではボタンを表示しない。再試行に成功した場合もボタンを消す。

## 安全上の範囲

再試行状態は現在の画面だけに保持し、再読み込みや別端末へ永続化しない。プロバイダーの重複防止期間を過ぎた古い操作を画面から再開させないためである。

今回、DB migration、環境変数、実メール送信、本番公開は行っていない。実接続の送信結果は未確認である。
