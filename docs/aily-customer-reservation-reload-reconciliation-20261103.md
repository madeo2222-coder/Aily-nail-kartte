# 顧客予約申請の再読込後照合（2026-11-03）

## 利用者ができること

顧客が予約希望を送信した直後に通信が切れたり応答が失われたりしてページを再読込しても、同じ予約をもう一度送らずに保存結果を確認できる。保存済みなら受付済みと表示してマイページへ案内し、保存を確認できない場合は送信ロックを維持したまま「予約結果を再確認」またはマイページ確認を選べる。

## 実装範囲

- ブラウザに残した予約申請の操作IDと入力内容を再読込後に復元する。
- 署名済みLINE顧客本人のセッションを必須とする読取専用 `GET /api/reservations` で、操作ID、顧客、サロンを照合する。
- 操作IDを予約IDとして保存できない旧DB構成では、同じ顧客、サロン、メニュー、担当者、開始・終了日時の完全一致だけを補助照合する。
- 保存済みを確認した場合だけ操作マーカーを消す。未検出、読取失敗、通信失敗は結果不明として再送を止め続ける。
- 通知だけが失敗した既存の再試行経路は、予約保存結果の照合対象から除外して従来の通知再試行を維持する。

DB migration、権限、環境変数、実顧客通知、実データ書込みは変更していない。

## 受入条件

1. 保存済み予約を持つ顧客が予約画面を再読込すると、予約POSTを再送せず受付済み表示になる。
2. 保存の有無を確定できない場合は予約ボタンが無効のままで、再確認とマイページへの導線が表示される。
3. 署名済み顧客以外は照合APIを利用できず、管理クライアントも開かれない。
4. 照合APIは予約本文を返さず、書込みや通知を行わない。
5. 通知再試行の保存情報は予約本体の結果不明として扱わない。
