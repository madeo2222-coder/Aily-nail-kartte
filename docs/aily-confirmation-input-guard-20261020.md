# 予約確定：不正JSONによる意図しない確定を拒否

## 不具合と修正

予約確定APIは `request.json()` の失敗時に空オブジェクトとして処理を続けていた。そのため、空の本文・途中で切れたJSON・JSONではない本文でも、既存予約の内容で確定RPCへ到達し得た。ローカルの実RequestとモックDBによる回帰テストで、修正前は空本文にHTTP 200を返すことを再現した。実DBで発生した事故を確認したものではない。

パース失敗時はHTTP 400 / `ok:false` / `confirmed:false` を返し、DBクライアント作成・予約読取・確定RPCへ進まないように変更した。スタッフ認証を先に行う順序、サロン制限、日時・競合検証、既存RPC、LINE再送方式には変更なし。

正常な予約一覧は明示的な `{}`、予約編集は編集内容をJSONで送っている。両画面の呼出元を照合し、明示的な `{}` による既存内容の確定は維持した。空本文への暗黙フォールバックだけを取り除く。
