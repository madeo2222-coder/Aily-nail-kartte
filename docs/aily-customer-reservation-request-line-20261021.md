# 顧客の予約変更・キャンセル希望：LINE送信結果の誤表示防止

## 今回の修正

確定済み予約で顧客が「変更希望」または「キャンセル希望」を送った際、店舗LINEが未設定・HTTP失敗・応答不明でも画面が「店舗へ送りました」と表示していた。予約自体は変更しない経路のため、この誤表示では依頼が店舗へ届かないまま顧客が完了と認識する可能性があった。

対象APIでLINEの受付結果を確認し、受付を確認できた場合だけ成功を返す。未設定・失敗・応答不明は顧客画面に失敗として表示し、送信済みとは扱わない。内部のLINE応答本文や資格情報は返さない。

申請中予約を顧客が直接変更・取消する経路も、予約保存と店舗LINE通知の結果を分離した。DB保存に成功した予約操作は取り消さず、LINE失敗・未設定・応答不明を黄色警告で表示する。「予約操作自体は完了」と「店舗通知は未確認」を同時に伝え、通知漏れを完全成功として隠さない。

保存成功後の予約再取得も操作結果と分離した。再取得に失敗しても保存成功表示を消さず、黄色警告と「最新情報を再読み込み」を表示する。表示中の古い内容から変更・取消を繰り返さないよう、最新情報を取得できるまで予約操作ボタンを無効化する。LINEログインを確認できない場合は従来どおり予約詳細を隠す。

予約操作の開始時に画面再描画を待たない即時ロックも追加した。変更・取消ボタンを素早く二度押ししても、最初の処理が完了するまでは2回目のPATCHを送らず、予約保存と店舗LINE通知の重複を防ぐ。

同じ予約状態・操作・依頼文から安定したUUID形式の `X-Line-Retry-Key` を生成する。応答喪失後に同じ内容を再試行した場合は同じキーと本文を使い、LINEが `409` と `X-Line-Accepted-Request-Id` を返した場合は、前回受付済みとして成功を返す。LINEの冪等受付期間を越えた重複防止や送達履歴の永続化は今回の範囲外。

## 利用者が確認できること

- 変更希望・キャンセル希望がLINEに受け付けられた場合だけ「店舗へ送りました」と表示される。
- 一時失敗または応答不明では成功表示にならず、同じ内容で再試行できる。
- 再試行時にLINEが前回受付済みと応答した場合は「送信済み依頼を確認しました。重複送信していません」と表示される。
- 申請中予約の直接変更・取消は保存済みの結果を維持し、店舗LINEだけ失敗した場合は黄色警告と店舗への直接連絡案内が表示される。
- 保存後の再取得に失敗した場合も保存成功は維持され、「最新情報を再読み込み」から復旧できる。再取得まで古い内容での再操作はできない。
- 変更・取消ボタンを素早く二度押ししても、同じ予約操作は1回だけ送信される。

DB、migration、予約状態、予約日時、認証方式、環境変数の値は変更していない。実DB・実LINE送信・本番公開は実施していない。
