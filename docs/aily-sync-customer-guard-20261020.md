# 遅延同期：別顧客の手入力予約への上書きを停止

## 再現した問題と修正

HPB/minimo共通の予約保存処理では、予約元の印がある同時刻付近の手入力予約を先に選び、その後にメールから照合した顧客IDを保存していた。両者の顧客IDが異なる場合でも、手入力予約の顧客を差し替え得た。実際の取込コードをモックDBで実行し、修正前は不一致ケースを拒否しないことを再現した。実データの誤更新事故を確認したものではない。

両方の顧客IDがあり一致しない場合、予約更新・新規予約登録の前に照合エラーで停止する。同一顧客と顧客未割当の手入力予約は、既存予約IDへの同期と手入力メモの保存を維持する。予約番号による既存予約検索、認証、SQL、設定は変更しない。

このガードの前に既存の顧客照合・自動作成処理が走るため、全ケースで一切のDB書込みがないとは主張しない。顧客を新規作成するケース、顧客不明・複数候補の解決、別端末の同時更新を原子的に防ぐことは今回の範囲外。HPBメールを用いた回帰テストで共通保存処理を実行しており、minimo実メールや実DBの通し確認ではない。
