# HPB / minimo Gmail同期: 書込み前の全件解析

## 利用者への影響

Gmailから取得できた予約メールを、DBへ最初の書込みを行う前に全件解析する。

同じ予約スレッドの新しい変更・キャンセルメールが書式変更などで解析できない場合、古い予約メールだけを先に反映して日時・メニュー・状態を巻き戻すことを防ぐ。解析失敗のスレッドだけを保留し、別スレッドは同期を継続する。

## 変更範囲

- `lib/hpb-mail-sync.ts`
  - DBへ接続しない純粋解析関数を公開し、通常同期でも同じ解析処理を再利用する。
- `app/api/hpb-gmail-sync/route.ts`
  - 対象メールを全件解析してから書込み工程へ進む。
  - 解析失敗と同じGmailスレッドは書込み前に保留する。
  - 解析失敗メールのスレッドIDが不明な場合は、対象予約メール全体を保留する。
  - 無関係な既知スレッドは従来どおり同期を継続する。

DB migration、RLS、認証設定、環境変数、実顧客へのLINE・メール送信は変更しない。

## 受入条件

1. 対象メールをすべて解析してから最初のDB同期関数を呼ぶ。
2. 同一スレッドの新しいメールを解析できない場合、読めた古いメールも同期しない。
3. 解析失敗が既知の別スレッドなら、無関係な予約メールは同期する。
4. 解析失敗メールのスレッドIDが不明なら、対象予約メール全体を同期しない。
