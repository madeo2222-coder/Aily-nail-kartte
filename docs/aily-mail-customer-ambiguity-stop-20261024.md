# 予約メールの顧客候補曖昧時の書込み停止（2026-10-24）

## 利用者への変更

HPB／minimoの新規予約で、同じ電話番号または同じ氏名を持つ顧客候補が複数あり、予約メールの情報だけでは1名に絞れない場合、顧客・予約を書き込む前にそのメールの同期を停止する。

従来は電話番号が複数顧客に重複し、氏名でも特定できない場合、新しい顧客をさらに自動作成する可能性があった。また、カナ候補が複数の場合は顧客未紐付けの予約を保存し得た。どちらもスタッフの手入力や後着メールと重複しやすくなる。

今回、候補が曖昧な予約はエラー結果として残し、対象メールではDB書込みを行わない。同じ同期処理内の無関係な予約メールは従来どおり処理を続ける。

## 検証内容

- 国内表記と国際表記で同じ電話番号を持つ既存顧客を2名用意
- 予約メールの氏名ではどちらにも絞れない状態を再現
- 顧客の追加、予約の追加・更新が一件も行われないことを確認
- 修正理由が分かるエラーを返すことを確認

## 変更しない範囲

- 電話番号または氏名で1名に特定できる通常予約
- 外部予約番号ですでに特定済みの予約・顧客
- キャンセル通知の既存予約照合
- Supabaseのschema、migration、RLS、環境変数
- 実Gmail、実LINE、実顧客への送信

実DBの重複電話番号を読み取る確認は未実施。Preview反映後は、許可されたテスト予約で曖昧な候補を誤って保存しないことを確認する。
