# Gmail予約同期: MIME件名の安全な復号

## 利用者に変わること

HPB／minimoの予約メール件名がRFC 2047形式で符号化されていても、同期前に日本語へ復号してから予約受付・変更・キャンセルを判定する。

特に、件名だけに「キャンセル」と書かれたメールが符号化されたままの場合に、通常予約として保存・更新することを防ぐ。

## 対象範囲

- UTF-8、ISO-2022-JPなど、実行環境の`TextDecoder`が対応する文字コード
- Base64（`B`）とQuoted-Printable相当（`Q`）のencoded-word
- 複数のencoded-wordに分割された日本語件名
- 通常の未符号化件名は従来どおりそのまま使用

未対応文字コードや壊れた符号化は推測で解析せず、本文取得失敗と同じ安全な再試行対象にする。GmailスレッドIDが判明していれば対象スレッドだけを保留し、無関係な予約同期は継続する。

## 検証

- Base64形式の日本語キャンセル件名を復号して同期処理へ渡す
- 連続したQ形式encoded-wordを結合して復号する
- 未対応文字コードをDB書込み前に拒否し、内部の文字コード名を画面へ露出しない
- 既存の本文MIME復号、スレッド単位の失敗隔離、予約同期回帰を維持する

## 未確認・変更していない範囲

- Aily実GmailのHPB／minimoメール件名
- Aily実DBへの保存と予約カレンダー再表示
- DB migration、RLS、環境変数、OAuth設定、実LINE／メール送信
- main、本番環境

この変更はアプリ側のメール読取処理だけで、Supabase変更は不要。
