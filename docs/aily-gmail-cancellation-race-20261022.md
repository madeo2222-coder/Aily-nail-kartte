# Gmail予約キャンセルの競合収束（2026-10-22）

## 利用者への効果

Gmail予約同期を定期実行と手動実行がほぼ同時に処理しても、同じHPB/minimoキャンセルを「保存失敗」と誤表示しにくくする。先に通常予約が作成された場合も、その予約を同じ処理内でキャンセル状態へ収束させる。

## 変更範囲

- 外部予約番号から作る決定的IDのINSERTが一意制約エラー（Postgres `23505`）になった場合だけ、同じIDを1回再読取する。
- 同一サロンですでにキャンセル済みなら成功として終了する。
- 同一サロンの通常予約が同時作成されていれば、既存のサロンID付き更新経路でキャンセルする。
- 別サロンまたは所属不明の行、再読取失敗、`23505`以外のDBエラーは成功扱いせず停止する。

DB schema、migration、Supabase設定、認証、環境変数、実LINE/メール送信は変更しない。

## 受入条件

1. 同じキャンセルが重複実行されても、片方のINSERT競合後に「キャンセル済み」として収束する。
2. 予約登録とキャンセルが競合した場合、同時作成された同一サロンの予約をキャンセルする。
3. 別サロンの行は更新しない。
4. 通常の保存エラーや更新結果不一致を成功扱いしない。

## 検証範囲

- 競合を再現するテストを追加し、修正前は2件失敗、修正後は成功することを確認した。
- 全回帰テスト、型検査、lint、fixture環境でのNext.js production buildを実施する。
