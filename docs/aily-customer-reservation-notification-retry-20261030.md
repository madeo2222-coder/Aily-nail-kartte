# 顧客予約の店舗通知再試行（2026-10-30）

## 利用者と目的

顧客が予約希望を送信したあと、予約保存には成功したもののスタッフ向けメールまたはLINE通知が明確に失敗した場合に、予約を二重作成せず通知だけを再試行できるようにする。

## 変更内容

- ResendまたはLINE APIが非成功応答を返した場合、予約保存済みであることと通知再試行可能であることをAPI応答で区別する。
- 予約画面に「店舗への通知を再試行」を表示する。
- 再試行では最初に送った予約内容と操作IDをそのまま使う。画面入力が途中で変わっても別予約として送らない。
- 再送時は既存のResend `Idempotency-Key` とLINE `X-Line-Retry-Key` を再利用し、片方だけ成功済みの場合も重複通知を抑止する。
- 通知結果が不明な通信断は従来どおり再送を止め、顧客へマイページ確認を案内する。

## 受入条件

1. 予約保存成功後にメールまたはLINEが非成功応答を返す。
2. 画面に予約保存済みと表示され、「店舗への通知を再試行」を操作できる。
3. 再試行リクエストが最初と同じ予約内容・操作IDを使う。
4. DB側が `already_created` を返し、新しい予約行を作らず通知処理だけが再実行される。
5. 通知成功後は通常の予約受付完了表示へ戻る。

## 検証範囲

- API実行テストで、予約作成成功→Resend 503・LINE成功→API 503（保存済み・再試行可）→同じ操作IDで再試行→`already_created`→両通知成功、を確認した。
- 画面実行テストで、再試行前後のリクエスト本文が完全一致し、成功後に再試行表示が消えることを確認した。
- 関連テスト、全回帰、型検査、変更ファイルのlint、fixture設定のNext本番buildを実施する。
