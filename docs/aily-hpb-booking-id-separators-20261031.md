# HPB予約番号のコピー由来区切り対策（2026-10-31）

## 対象

- HPBメール同期の予約番号解析と既存予約照合
- 実DB変更、実LINE／メール送信、環境変数変更、本番公開は含まない

## 問題

HTMLメールの転送やコピー＆ペーストで、HPB予約番号の英字・数字の間に通常空白やゼロ幅文字が混ざることがある。既存実装は連続した英数字だけを受け付けるため、同じ予約番号でも解析を停止し、スタッフの手入力や時間差重複につながる可能性があった。

## 変更

- HPB予約番号の既存形式（英字1〜4文字＋数字6文字以上）を維持したまま、文字間の通常空白・タブ・ゼロ幅文字を許容する
- 取得後はミニモと共通の外部予約番号正規化を通し、既存予約照合と決定的IDを同じ値へ収束させる
- 後続する別の英数字を予約番号の一部として切り捨てず、不正な番号はDBアクセス前に拒否する

## 受入条件

- `A123456` と `Ａ １ ２３ ４５６`（ゼロ幅文字混在）が同じ `A123456` として解析される
- 保存済みの `HPB予約番号：A123456` と一致し、追加登録ではなく既存予約更新へ進む
- `A 123456 X` のような別英数字が続く値は、`A123456` だけを誤採用せず書込み前に停止する
- 関連テスト、全回帰テスト、型検査、lint、fixture環境のNext本番buildが成功する
