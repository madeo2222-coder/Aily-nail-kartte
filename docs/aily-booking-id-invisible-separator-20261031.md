# 外部予約番号の不可視区切り文字対策（2026-10-31）

## 対象

- HPB／ミニモのメール同期で使う外部予約番号の正規化、照合、決定的ID生成
- 実DB変更、実LINE／メール送信、環境変数変更、本番公開は含まない

## 問題

転送メールやコピー＆ペーストを経由した予約番号に、通常の空白やゼロ幅文字が混ざることがある。従来は外側の空白だけを除去していたため、同じ予約番号でも既存予約との照合や決定的IDが一致せず、別予約として扱われる可能性があった。

## 変更

- Unicode幅・大小文字の既存正規化に加え、予約番号内の空白、ゼロ幅スペース、ゼロ幅非接合子／接合子、word joiner、BOMを除去する
- 正規化した値を既存予約照合と決定的ID生成の両方で共通利用する
- 全角文字、途中の通常空白、不可視文字が混在しても既存予約へ収束する回帰テストを追加する

## 受入条件

- `MINIMO-123`、`ＭＩＮＩＭＯ - １２３`、不可視文字を含む同番号が同じ予約番号・同じ決定的IDとして扱われる
- 既存予約のメモに保存済みの番号と一致し、追加予約ではなく既存予約更新へ進む
- 関連テスト、全回帰テスト、型検査、lint、fixture環境のNext本番buildが成功する

## 未検証範囲

- 実際のHPB／ミニモ受信メールによる認証済みE2E
- 実顧客へのLINE／メール送信
