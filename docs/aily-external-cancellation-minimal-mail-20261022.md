# 外部予約の簡易キャンセルメール対応（2026-10-22）

## 利用者・目的

スタッフがHPB／minimoの予約番号だけを含むキャンセル通知を同期した場合でも、すでに保存済みの対象予約をキャンセルへ更新できるようにする。

## 納品範囲

- HPB／minimo共通のメール解析とキャンセル処理
- 予約番号または予約IDで既存予約を一意に特定できる場合は、氏名・来店日時が通知にない場合もキャンセル更新
- 一致する既存予約がなく、氏名・来店日時も不足する場合は新規予約を作らず停止
- DB schema、migration、環境変数、Gmail設定、LINE送信は変更しない

## 受入条件

1. HPBの予約番号だけを含むキャンセル通知で既存予約がキャンセルになる。
2. minimoの予約IDだけを含むキャンセル通知で既存予約がキャンセルになる。
3. 同じ簡易通知で既存予約が見つからない場合、予約・顧客の書込みは0件となる。
4. 通常の予約メールでは従来どおり氏名と来店日時を必須とする。
5. 詳細を含む先行キャンセル通知は、従来どおりキャンセル済み予約として保存できる。

## 実施した確認

- 修正前に、HPB／minimoの簡易キャンセル通知が氏名不足でDB照合前に停止することを再現
- 修正後に、両通知が既存予約をキャンセル更新することを模擬DBで確認
- 既存予約がない両通知は、必要項目不足の明示エラーとなり書込み0件で停止することを確認
- 通常予約の不正日時拒否、既存キャンセル維持、先行キャンセル保存、顧客不一致拒否を含む関連回帰を確認

## 未検証範囲

- Aily実DBでの保存・再表示
- 認証済みスタッフ画面からの同期操作
- 実顧客への通知、LINE送信、本番反映

## 現場受入手順

許可されたテスト予約を使い、予約を保存した後に予約番号だけのキャンセル通知を同期し、予約一覧で同じ予約がキャンセル表示になることを確認する。予約番号に一致する予約がない通知では新規予約が増えないことも確認する。

## 残件・次工程

検証済み成果を次回の6時間バッチ候補として保存する。Preview反映後に、許可されたテスト予約と実Gmailで入力→保存→再表示を確認する。実DB変更、実送信、本番公開は既存の承認条件を維持する。
