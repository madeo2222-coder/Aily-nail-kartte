# 別日時依頼LINEの予約更新後ロック解除（2026-10-30）

## 利用者ができること

スタッフが申請中予約へ別日時入力のLINEを送り、その後に顧客が同じ予約へ新しい希望日時を保存した場合、予約編集画面を再読込すると新しい申請に対して別日時入力を再度依頼できます。

送信結果が確定していない同一内容の再送防止は維持します。予約が更新されていない間は、ページを再読込しても23時間の送信済み／履歴確認ロックが続きます。

## 変更内容

- スタッフ予約編集APIの既存予約読取へ `updated_at` を追加した。
- 別日時依頼LINEのブラウザ保存ロックを予約IDだけでなく、読取時の `updated_at` と組み合わせて保存する。
- 再読込時の予約リビジョンが一致する場合だけロックを復元する。
- 顧客の希望日時変更などで `updated_at` が進んだ場合は古いロックを削除する。
- 予約リビジョンを持たない旧形式のロックは、公開直後の重複送信を避けるため、初回読取時のリビジョンへ安全側で移行する。

DB migration、環境変数、LINE送信処理、通知台帳の排他処理は変更していません。

## 受入条件

- 同じ予約リビジョンでは送信済み／結果不明のLINEを再送できない。
- 顧客が希望日時を変更し、予約の `updated_at` が進んだ後に画面を再読込すると古いロックが消える。
- 旧形式の予約IDだけの有効なロックは、重複送信を許さず新形式へ移行する。
- スタッフ編集APIは所属店舗の予約だけを読み、予約リビジョンを画面へ返す。
