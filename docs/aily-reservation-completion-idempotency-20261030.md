# 予約完了更新の応答喪失時再試行

## 利用者が新しくできること

旧共有ログインの来店登録で、来店履歴・支払い・写真の保存後に予約を「完了」へ更新した際、サーバーでは更新済みなのにブラウザが応答を受け取れなかった場合でも、画面が完了更新だけを1回再試行して安全に成功へ収束できる。

これにより、登録結果が不明なため同じ来店を再登録する必要がなくなり、予約状態だけが未確認のまま残るケースを減らす。

## 実装範囲

- 表示時点の予約状態から「完了」へ進められる場合に限り、現在状態が既に「完了」なら再試行を成功として返す。
- 完了更新の通信切断、HTTP 500、成功応答の解析不能では、来店履歴を再保存せず同じ完了更新だけを1回再試行する。
- HTTP 409、認証拒否など結果が確定した応答は自動再試行しない。
- 表示時点の顧客ID一致を引き続き必須にする。
- 「予約確定」など完了へ直接進められない状態を元にした要求は、現在状態が完了でも再試行扱いにしない。
- 既存の `来店` 応答喪失復旧、来店履歴・支払い照合、サロン所属制限、署名済み共有ログイン、比較書込みを維持する。
- DB migration、環境変数、実送信、実データ変更は含まない。

## 確認版の受入条件

1. 旧共有ログインで予約から来店登録を行う。
2. 来店履歴、支払い、必要な写真が1件だけ保存される。
3. 予約が「完了」として再表示される。
4. 完了更新の応答を意図的に失わせても、画面が完了更新だけを1回再試行し、来店履歴や支払いを増やさず成功する。
5. 古い画面の顧客ID不一致、または完了へ直接進められない状態からの要求は拒否される。

実DB上の入力→保存→再表示、通常のスタッフ認証、現場受入、本番反映は未実施。確認版への反映は、Aily全体の6時間間隔と単一統合バッチ条件を満たした時点で他の検証済み成果とまとめる。
