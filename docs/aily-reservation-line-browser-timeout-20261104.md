# 予約LINE通知のブラウザ待機上限（2026-11-04）

## 利用者への変更

スタッフ予約一覧と予約編集画面で、予約確定LINE・確定LINE再試行・別日時入力依頼の応答が返らない場合でも、画面が無期限に処理中のまま残らないようにした。ブラウザは15秒で応答待ちを終了し、既存の「送信履歴を確認する」状態へ移る。

送信結果が不明な場合は成功や失敗を推測せず、同じLINEを繰り返し送らない。既存の予約確定、表示中予約のスナップショット検証、タブ間送信ロック、送信済み判定、別日時依頼の予約版管理は維持する。

## 変更範囲

- `lib/reservation-confirmation-line-retry.ts` にLINE通知POSTの共通15秒上限を追加
- `/reservations` の予約確定後LINE通知に共通処理を使用
- `/reservations/edit/[id]` の確定LINE、再試行、別日時依頼に共通処理を使用
- 応答喪失時は既存の履歴確認ロックと不明結果表示へ収束

DB、migration、認証、環境変数、LINE送信APIのサーバー処理、実顧客データは変更していない。
