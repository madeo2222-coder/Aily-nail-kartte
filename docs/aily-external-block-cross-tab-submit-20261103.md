# 外部予定登録の別タブ重複防止（2026-11-03）

## 利用者・目的

スタッフがHPB・minimo等の外部予約を手入力するとき、外部予約ブロック登録画面を複数タブで開いていても同じ内容を同時送信しないようにする。既存の画面内連打防止、操作IDによる冪等化、保存結果の再読込照合、予約カレンダーの重複確認は維持する。

## 今回の範囲

- 外部予定の作成POST直前に、同じ操作IDを送信できるタブをブラウザ内で1つに限定する。
- タブごとの所有IDを `sessionStorage` に保持し、同じタブの再読み込みと別タブを区別する。
- 別タブが送信中の場合はPOSTせず、予約カレンダーで最新状態を確認するよう案内する。
- 通信結果が不明な場合は所有権を5分間保持し、古い別タブからの即時再送を止める。
- 同じタブの再読み込みでは所有IDと操作IDを再利用し、既存の保存済み・未保存照合から安全に復旧する。
- 保存成功または明示的なAPI拒否では、従来どおり操作IDと所有権を整理する。

DB、migration、認証、環境変数、実データ、実LINE・メール送信、本番公開は変更しない。

## 受入条件

1. 同じ外部予定と操作IDを2つのタブが送信しようとしても、作成POSTへ進むのは所有権を取得した1つだけである。
2. 所有権を取得できない画面には、別画面で登録中であることと予約カレンダー確認導線が表示される。
3. 同じタブを再読み込みした場合は、応答喪失後も同じ操作IDで保存結果を照合し、確認済みの未保存操作だけを再試行できる。
4. 所有権の期限後は、閉じられたタブが残した操作を別タブから回収できる。
5. 保存成功、API拒否、応答喪失、再読込照合、予約カレンダー表示の既存動作が退行しない。

## 検証限界

Aily実DBへの書込み、認証済み実画面の複数タブ操作、実LINE・メール送信は実施しない。ブラウザ保存領域が利用できない場合は、画面内ガードとサーバー側の操作IDに依存する。DB側の関数・migration適用状況は今回変更・断定しない。
