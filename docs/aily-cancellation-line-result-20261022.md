# 予約キャンセルLINE：予約結果と通知結果の分離

## 1. 利用者・目的

予約をキャンセルするスタッフが、予約保存の成否と顧客LINE通知の成否を混同しないようにします。特に通信断・タイムアウト時に「LINE送信失敗」と断定せず、二重通知につながる再送を避けます。

## 2. 納品範囲

- 予約キャンセル自体が保存済みなら、青い成功欄へ「予約をキャンセルしました」と表示する。
- LINE未連携、明示的な送信失敗、送信結果不明は、予約成功とは別の黄色警告欄へ表示する。
- LINE APIの応答を取得できなかった場合は `unknown` とし、「再送せず送信履歴を確認」と案内する。
- LINE APIが明示的に拒否した場合は、従来どおり `failed` として表示する。

## 3. 受入条件

- LINE成功時は予約キャンセルと送信成功が表示される。
- LINE未連携・明示失敗時も予約キャンセルは成功として維持され、通知警告だけが黄色で表示される。
- 通信断・タイムアウト時は「送信結果不明」と表示され、失敗断定や即時再送を促さない。
- 応答不明後も予約を再キャンセルせず、LINE送信履歴を確認するよう案内される。

## 4. 実際に確認した結果

- LINE応答喪失を `unknown` として返し、失敗文言を表示しないテスト。
- 明示的なLINE拒否を `failed` のまま維持するテスト。
- 予約キャンセル成功とLINE警告を別表示へ分ける画面契約テスト。
- 既存の取消し冪等性・同時更新競合テストを含む対象8件成功。

## 5. 残件・未検証

実スタッフ認証、実DB書込み、実LINE送信、Preview、本番では未検証です。送信結果不明後の安全な自動再試行は、同一のLINEリトライキーを永続保持する取消し通知専用台帳が必要なため今回の範囲外です。DB、migration、認証、環境変数は変更していません。
