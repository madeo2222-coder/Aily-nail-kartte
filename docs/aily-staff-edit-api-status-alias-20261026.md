# 予約編集APIの旧ステータス互換

## 対象業務

スタッフが予約編集画面で、旧データに全角英字や空白を含む確定状態が保存された予約を確認・更新する操作。

## 修正内容

画面側で正しく「予約確定」と表示できても、更新APIが状態を完全一致で判定して保存を拒否する不整合を修正した。確定・取消・稼働中の判定と重複確認の除外判定を、既存のワークフロー正規化へ揃えた。

DBに保存されていた元の状態値は引き続き `expectedStatus` として更新条件に使用する。このため、別操作による同時更新を検知する楽観ロックは維持される。許可する状態遷移、外部予約の編集禁止、DB定義、認証、LINE通知は変更していない。

## 確認したケース

- ` ＣＯＮＦＩＲＭＥＤ ` を確定済みとして扱い、確定状態のまま更新できる。
- 過去日時の確定済み予約で、日時を変えずにメモなどを修正できる。
- 読込時の生の状態値を更新条件に残し、同期後の古い画面からの上書きを防ぐ。
- 未確定予約を編集画面から直接確定する既存の禁止を維持する。
