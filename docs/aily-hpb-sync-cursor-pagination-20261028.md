# HPB／minimo同期の設定値非依存ページング修正（2026-10-28）

## 利用者への効果

HPB／minimoの予約同期で候補が多い場合でも、Supabase Data APIの最大返却件数が500件などに設定されていても全候補を確認します。501件目以降に既存予約または顧客がある場合に、新しい予約や顧客を重複作成する問題を防ぎます。

## 修正内容

- 要求したページ幅と実際の返却件数が同じだと仮定するoffsetページングを廃止。
- ID昇順と最終取得IDを使うカーソルページングへ変更。
- 顧客候補、外部予約番号候補、同時間帯の手入力予約候補の3経路を同じ方針で修正。
- 空ページまで読み切ってから一致・一意性を判定。
- カーソルが進まない異常と後続ページの取得失敗は、書込み前に安全停止。

## 確認内容

- Data API最大返却数500件の再現条件で501件目を取得する回帰テスト。
- 3つの候補検索すべてで後続ページを取得すること。
- 後続ページのエラー時に予約・顧客を書き込まないこと。
- 全回帰テスト、型検査、lint、本番相当fixture build。

## 反映範囲と未検証

Aily実DB、実Gmail、実顧客データでは未検証です。DB migration、権限、環境変数、実送信は変更しません。この成果は保存コミットとして準備し、統合ブランチとPreviewには次の許可済み単一バッチまで反映しません。
