# 予約メールの同名顧客・電話番号不一致ガード（2026-10-24）

## 利用者への変更

HPB／minimoの新規予約を顧客へ紐付ける際、予約メールと既存顧客の電話番号が明確に異なる場合は、氏名が同じだけでは既存顧客へ紐付けないようにした。

従来は電話番号の完全一致が見つからなくても、同名の既存顧客が1名ならその顧客へ予約を紐付けていた。同姓同名の別顧客がいると、その顧客の詳細画面へ別人の予約が表示される可能性があった。

今回の判定は次のとおり。

- 電話番号が一致する既存顧客は従来どおり優先する
- `090...` と `+81 90...`／`+81 (0)90...` は同じ国内番号として比較する
- 予約メールに電話番号がない場合は、従来どおり氏名で補完する
- 既存顧客の電話番号が未登録の場合は、従来どおり氏名で補完する
- 両方に電話番号があり、異なる場合は氏名・カナ一致の候補から除外する
- 一致する顧客がなく新規予約の場合は、外部予約番号から決定的に作る顧客へ保存する

## 検証内容

同じ氏名で異なる電話番号を持つ既存顧客を用意し、新規予約がその顧客へ紐付かず、予約番号に対応する新規顧客と予約へ保存されることを自動テストで確認する。あわせて、国内表記と国際表記の違いだけで同じ顧客を分けないことを確認する。

## 変更しない範囲

- 既に外部予約番号で特定済みの予約・顧客の再同期
- スタッフが手動修正した既存予約の顧客紐付け
- Supabaseのschema、migration、RLS、環境変数
- 実Gmail、実LINE、実顧客への送信

実DB上の同姓同名顧客を使った入力→保存→顧客詳細での再表示は未検証。Preview反映後に許可されたテスト予約で確認する。
