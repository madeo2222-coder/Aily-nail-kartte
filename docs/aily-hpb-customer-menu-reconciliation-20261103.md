# HPB／minimo遅延同期の自由入力メニュー誤判定修正（2026-11-03）

## 利用者・目的

スタッフが先に手入力した予約へHPB／minimoの予約メールが後から届く運用で、通常予約の自由入力メニューに予約サイト名が含まれても同じ予約を二重作成しないための修正です。

## 修正した問題

通常予約の「その他・自由入力」メニューに「ミニモで見たデザイン」「ホットペッパー風ネイル」などを入力すると、予約サイト名だけで予約元を判定していました。そのため、実際の予約元が別サービスの場合、顧客・日時・スタッフが一致する手入力予約を再利用できず、新規予約を作る可能性がありました。

## 変更内容

- メニュー欄は、予約サイト名に加えて「予約」「booking」「受付」「外部」の明示がある場合、または予約サイト名だけの既存表記の場合に予約元として扱います。
- デザイン名など通常メニューの自由入力に含まれる予約サイト名は、予約元の印として扱いません。
- `ホットペッパー予約`、`HPB`、`minimo booking`、`ミニモ`など既存の明示表記は維持します。
- 構造化行 `外部予約種別：...`、予約番号、顧客・日時・スタッフ、曖昧候補、キャンセル済み予約に関する既存の保護は維持します。
- DB、migration、認証、通知設定の変更はありません。

## 受入条件

同一顧客・日時・スタッフの手入力予約の自由入力メニューに別サービス名が含まれても、後着したHPB／minimoメールは既存予約を更新し、新しい予約行を作らないこと。明示的な外部予約メニューは従来どおり予約元として識別すること。
