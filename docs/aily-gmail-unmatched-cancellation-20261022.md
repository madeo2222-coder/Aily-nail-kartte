# Gmail先行キャンセルの永続化（2026-10-22）

## 利用者が新しくできること

HPB／minimoのキャンセルメールだけを先に取得した場合でも、予約をキャンセル済みとして保存できます。元の予約メールが一時的に取得できず、後日の同期で初めて届いても、予約が有効な状態で復活しません。

## 操作手順

従来どおりスタッフ画面のGmail予約同期を実行します。新しい入力や設定変更はありません。

## 今回の最小納品単位

- 外部予約番号に一致する予約がないキャンセルメールを、決定的な予約IDでキャンセル済み予約として保存
- サロン、日時、メニュー、担当（特定できた場合）、外部予約番号、キャンセルメール本文を保持
- 顧客の検索・自動作成は行わず、キャンセル処理だけで顧客レコードを増やさない
- 既存予約のキャンセル更新、別サロン防止、重複候補停止の動作を維持
- 同じ元予約メールを後から処理しても、キャンセル済みを検出して書込み前に停止

## 実際に確認した業務

1. 元予約がDBにない状態でキャンセルメールを処理
2. キャンセル済み予約が1件だけ挿入されることを確認
3. 同じ予約番号の元予約メールを後から再処理
4. 顧客検索・予約更新を行わず、キャンセル済みのまま収束することを確認
5. 挿入結果が0件、別ID、DBエラーの場合に成功扱いしないことを確認

## 受入条件

1. 許可されたテスト予約のキャンセルメールだけを同期対象にする
2. 予約一覧で対象がキャンセル済みとして保存・再表示される
3. 元予約メールを同期対象へ戻して再実行する
4. 対象予約が確定状態へ戻らず、重複予約も作成されない

## 現時点の区分・残件・次の納品予定

コードと自動テストでの確認版です。Aily実DB、実Gmail、実顧客、実LINE、本番では未確認です。最新Vercel試行から6時間経過後、先行する未反映予約同期修正と単一Previewバッチへまとめ、許可されたテスト予約で入力→保存→再表示→再取込を確認します。

本人によるDB操作、migration、接続切替、秘密情報の提出は不要です。
