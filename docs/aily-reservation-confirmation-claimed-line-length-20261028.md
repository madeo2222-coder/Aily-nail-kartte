# 予約確定LINEの保存済み再送本文を送信前に確認する修正（2026-10-28）

## 利用者への効果

予約確定LINEの安全な再試行で、通知台帳から返された保存済み本文がLINEの文字数上限を超えている場合、外部送信せずスタッフへ通知状態の確認を案内します。

## 修正内容

- 現在生成した本文に加え、通知claim後に返る保存済み本文も5000 UTF-16コード単位以下か確認する。
- 上限超過時はLINE APIを呼ばず、通知台帳を失敗状態へ戻す。
- 台帳の完了記録に失敗しても、既知の未送信結果として再送をロックする。
- 上限内の再試行、同じ再送キー、結果不明時の再送防止は維持する。

## 確認条件

- 現在生成した本文が上限内でも、保存済み本文が上限超過ならLINE送信0件になること。
- 失敗完了記録に予約ID・試行回数・失敗状態を渡すこと。
- スタッフ画面へ `message_too_long` と再送不可を返すこと。

## 反映範囲と未検証

Aily実DB、実顧客LINE、実機、Preview、本番は未検証・未変更です。DB migration、RLS、環境変数、実送信の変更はありません。
