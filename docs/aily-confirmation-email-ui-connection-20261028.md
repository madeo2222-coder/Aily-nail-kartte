# 予約確定メールをスタッフ操作へ接続（2026-10-28）

## 今回の納品単位

予約確定メールAPIは安全化済みでしたが、予約一覧と予約編集の「予約確定」操作から呼ばれていませんでした。スタッフが予約を確定した直後に、既存LINE通知と予約確定メールの両方を実行し、それぞれの結果を画面へ表示するよう接続しました。

- 予約一覧の確定ボタンを「予約確定・通知送信」へ変更
- 予約編集画面の確認文でLINE・メール通知を明示
- 確定APIが成功または確定済みを返した場合だけ通知APIを実行
- LINE失敗時もメール処理を続け、メール失敗時も予約確定とLINE結果を失わない
- メール未登録、外部予約、送信設定不足、応答不明など、メールAPIの結果をスタッフへ表示
- 予約確定APIの結果が不明または失敗なら通知APIを呼ばず、最新状態の再読込を優先

## 変更していないもの

- Aily Supabaseのschema、RLS、権限、migration
- Vercel環境変数、Resend設定、LINE設定
- メールAPIの宛先再確認、サロン境界、外部予約除外、Resend冪等キー
- LINE送信台帳と再試行ロック
- 実顧客へのLINE・メール送信
- main / production

## 受入条件と検証限界

Previewでは、許可されたテスト予約とテスト用のLINE・メール宛先を使い、予約確定後に状態が再表示され、LINEとメールの結果が別々に表示されることを確認します。実送信、実DB、受信メール表示は未確認です。Resendの冪等キー保持は24時間のため、応答不明時の再試行はAPIが案内する期間内に限定します。
