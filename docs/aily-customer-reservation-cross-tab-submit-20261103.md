# 顧客予約の別タブ二重送信防止（2026-11-03）

## 利用者・目的

顧客が予約申請画面を複数タブで開いていても、同じ予約内容を同時送信して重複申請することを防ぐ。既存の同一画面連打防止、予約作成の操作ID、結果不明時の再確認、通知だけの再試行は維持する。

## 今回の範囲

- 予約作成前に、ブラウザ内で操作IDごとの送信所有権を1タブだけが取得する。
- 他タブが送信中ならAPIへPOSTせず、予約結果の再確認とマイページ確認へ案内する。
- 通信結果が不明な場合は所有権を5分間保持し、その間の再送を防ぐ。
- 既知の成功・競合・入力エラーでは既存の操作ID整理を維持する。
- 店舗通知だけを再試行できる状態へ移るときは、予約作成の所有権を残さない。

DB、migration、認証、環境変数、実顧客へのLINE・メール送信、本番公開は変更しない。

## 受入条件

1. 同じ操作IDに対して2つのタブが送信を試みても、予約作成POSTへ進むのは1つだけである。
2. 所有権を取得できなかった画面は送信せず、「予約結果を再確認」を表示する。
3. 結果不明の送信は再読込後も既存の保存済み照合を利用できる。
4. 送信画面が閉じられた場合も、5分経過後は別タブが照合・再試行へ進める。
5. 通知再試行、既知の競合後の再入力、保存済み確認の既存動作が退行しない。
