# 予約編集画面の確定操作表示修正（2026-11-03）

## 対象業務

スタッフが予約編集画面で申請中の予約を確定し、来店・完了後の予約や外部予定を確認する業務。

## 問題

予約編集画面では、予約確定済みとキャンセル以外の状態に一律で「予約確定にする」を表示していた。そのため、来店済み・完了済みの予約や顧客を持たない外部予定にも確定操作が見え、押すとAPIで拒否されるか、状態を巻き戻すように見える不整合があった。

## 修正

- `requested`、`予約申請中`、`予約受付`、`予約` の正規化済み申請状態だけに確定操作を表示する。
- HPB/minimo同期予約と外部予定には確定操作を表示しない。
- 来店・完了系の状態は現在状態を表示し、確定操作を表示しない。
- 画面上の表示条件に加えて、確定処理の入口でも同じ条件を確認し、古い画面状態からの誤操作を送信前に止める。

## 検証範囲

- 申請状態の全表記と全角・空白表記を確認する。
- 確定済み、来店、完了、キャンセルが確定対象にならないことを確認する。
- 外部予定・外部同期予約・進行済み予約の画面分岐と送信前ガードを確認する。

実DB書込み、実LINE・メール送信、現場認証、本番反映は実施していない。
