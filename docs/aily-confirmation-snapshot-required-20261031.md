# 予約確定時の最新内容照合を全経路で必須化（2026-10-31）

## 対象

- スタッフによる申請中予約の確定API
- 予約一覧と予約編集画面から送る表示時点スナップショット
- 実DB変更、実LINE／メール送信、環境変数変更、本番公開は含まない

## 問題

現行の予約一覧・編集画面は、顧客、担当、メニュー、日時、状態、メモの表示時点スナップショットを送っている。一方で、旧来の空JSONだけを送る経路もAPIが受け付けていた。この例外経路では、古いタブが別端末や予約同期による更新を確認せずに確定処理へ進む可能性があった。

## 変更

- 予約確定APIは編集有無にかかわらず7項目の表示時点スナップショットを必須にする
- 空JSONや一部項目だけの要求は、DB読取前に再読み込み案内を返す
- DBから読んだ最新予約と全7項目が一致する場合だけ原子的な確定RPCへ進む
- 現行の予約一覧・予約編集画面は既に全項目を送信しているため、通常操作は変更しない

## 受入条件

- 空JSONの確定要求は特権DB接続を作る前に拒否する
- 一部のスナップショット項目が欠けた要求も拒否する
- 顧客、担当、メニュー、日時、状態、メモのいずれかが更新済みなら確定しない
- 最新内容が一致する通常の予約確定、重複枠拒否、確定済み再実行防止を維持する
