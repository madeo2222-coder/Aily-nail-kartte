# HPB・minimo 同期停止時の不要顧客作成防止（2026-10-30）

## 利用者ができること

HPB・minimo の予約メールと同時刻帯に、候補を1件へ特定できない手入力予約がある場合、同期は従来どおり安全に停止します。このとき、予約へ使われない顧客レコードを先に作成しないようにしました。

## 変更範囲

- メールの電話番号・氏名で既存顧客を特定できず、新しい外部顧客を作る場合だけ、手入力予約候補を先に確認する。
- 同媒体の候補が複数ある場合や、別顧客に紐づく候補しかない場合は、顧客・予約のどちらも書き込まず停止する。
- 顧客未設定の同媒体候補が1件なら、外部顧客を作成し、その手入力予約へ同期する。
- 既存顧客を再利用できる予約、既存の外部予約、キャンセル処理の動作は維持する。

DB migration、認証、環境変数、Gmail設定、LINE・メール送信、実データの変更はない。

## 受入条件

1. 顧客未設定の同媒体候補が複数ある場合、顧客を作成せず同期を停止する。
2. 別顧客に紐づく同媒体候補がある場合、顧客を作成せず同期を停止する。
3. 顧客未設定の同媒体候補が1件なら、顧客を作成してその予約を更新し、新しい予約行を追加しない。
4. 既存の顧客照合、外部予約再実行、キャンセル、同時変更保護を維持する。

## 検証範囲

- 曖昧な手入力予約で書込み0件となる回帰テスト
- 別顧客に紐づく手入力予約で書込み0件となる回帰テスト
- 顧客未設定の1件へ顧客作成後に収束する回帰テスト
- HPB・minimo同期の関連テスト、全自動テスト、型検査、lint、ローカルproduction build

Aily実DB、実Gmail、認証済みスタッフ画面での入力から再表示までは未検証です。DB制約を追加していないため、別端末で同時に手入力予約が増える競合を完全に原子化する変更ではありません。
