# Gmail予約の同時再処理による上書き防止（2026-10-24）

## 利用者に変わること

同じHPB／minimo予約メールが並行して処理され、片方が先に予約を保存した場合、遅れた処理は同じメールが保存済みであることを確認して終了する。

先に保存された直後にスタッフが担当・メニュー・日時・メモを修正しても、遅れた同期処理が不要な再更新を行わないため、現場の修正を維持できる。

## 安全性を維持する範囲

- 同じ外部予約IDでも、保存済みメール本文が異なる変更メールは従来どおり更新候補として処理する。
- キャンセル済み予約は従来どおり復活させない。
- 別サロン、顧客紐付け不一致、同時変更の競合検知は維持する。
- DB schema、migration、RLS、環境変数、実Gmail、実DB、実通知は変更しない。

## 受入条件

1. 同一メールの並行INSERT競合後は追加UPDATEを行わない。
2. 先行処理後のスタッフ修正済み担当・メニュー・日時・メモを保持する。
3. 内容が異なる変更メールは同期を省略しない。
4. 既存のキャンセル・別サロン・顧客・日時競合テストを維持する。
