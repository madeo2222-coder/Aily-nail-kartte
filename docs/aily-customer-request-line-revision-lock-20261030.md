# 顧客の変更・キャンセル希望LINEロックを予約更新へ追従

## 利用者ができること

顧客が確定済み予約から変更希望またはキャンセル希望を店舗へ送った後、スタッフが予約日時・メニュー・担当などを更新した場合、新しい予約内容に対して改めて希望を送れる。

同じ予約内容のままでは従来どおり送信済みロックを維持し、画面再読込や連打による重複LINEを防ぐ。

## 変更内容

- ブラウザ保存の送信済みロックへ、APIが返す予約 `requestRevision` を保存する。
- 再表示時の予約revisionが保存時と一致する場合だけロックを復元する。
- 予約revisionが変わっていた場合は古いロックを削除し、新しい依頼を許可する。
- 旧v1ロックは現在の予約revisionへ一度だけ移行し、既存利用者の重複送信防止を維持する。
- DB、RLS、認証、LINE API、環境変数は変更しない。

## 受入条件と検証

- 同じ予約revisionでは、変更希望・キャンセル希望の各送信済みロックが再読込後も復元される。
- 予約revisionが変わると古いロックが削除される。
- 旧v1ロックがv2へ移行される。
