# Gmail予約同期：件名だけにあるキャンセル判定

## 原因と修正

Gmail同期はメール件名と本文を取得していたが、HPB／minimoの予約解析には本文だけを渡していた。本文に既存のキャンセル定型句がなく、件名だけが「予約キャンセル」になっている通知は通常予約として扱われ、既存予約を確定状態へ戻し得た。

Gmail同期から件名を解析処理へ渡し、NFKC正規化後の件名に「キャンセル」または `cancel` がある場合はキャンセルとして扱う。予約番号、顧客、日時等は従来どおり本文から解析し、DBの予約メモへ保存する原文にも件名を混入させない。本文貼り付けによる手動同期は引数を追加せず従来動作を維持する。

## 次の納品

| 項目 | 内容 |
| --- | --- |
| 利用者・目的 | スタッフが件名だけで示されるHPB／minimoキャンセルも予約カレンダーへ正しく反映できる |
| 範囲 | Gmail同期ルート、共通メール解析、HPB／minimo件名回帰テスト。DB/schema/env変更なし |
| 受入条件 | 件名がキャンセル、本文が通常予約形式でも既存予約をキャンセル更新し、件名を予約メモへ保存しない |
| 残件 | 次回単一Preview反映、通常のスタッフ認証と許可されたテストメールによる保存→再表示の実接続受入 |
| Preview | 6時間間隔中のため本記録時点では未反映。次回最短は2026-10-22 02:06:45.791 JSTで、直前に全環境を再確認する |

## 検証と限界

- 修正前はHPB／minimoの件名キャンセル2件が通常予約判定となることを実取込関数＋模擬DBで再現した。
- 修正後は両件ともキャンセル更新となり、Gmailルートが取得件名を同期関数へ順序どおり渡すことを確認した。
- 実Gmail受信、Aily実DB、実顧客データ、実LINE送信は実施しない。プロバイダーの全件名形式を保証するものではない。
- 本変更はキャンセル判定材料の欠落だけを修正し、既存の決定的予約ID、遅延手入力照合、キャンセル再処理ガード、更新結果確認を維持する。
