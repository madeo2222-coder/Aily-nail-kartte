# HPB / minimo Gmail同期: 本文取得結果からスレッドIDを回収

## 利用者への影響

Gmailのメール一覧にスレッドIDが含まれない場合でも、本文取得結果に含まれるスレッドIDを同期判定へ使用する。

これにより、同じ予約スレッド内で新しい変更・キャンセルメールの本文取得に失敗した際、一覧上のスレッドIDが欠けた古い予約メールだけを別件として先に反映することを防ぐ。取得できなかったメールと同じスレッドだと本文取得結果から確認できたメールは、DB書込み前にまとめて保留する。

## 変更範囲

- `app/api/hpb-gmail-sync/route.ts`
  - Gmail本文取得レスポンスの `threadId` を受け取る。
  - 本文側の `threadId` を優先し、一覧側にしかない場合は従来値へフォールバックする。
  - 本文取得自体が失敗したメールでは、一覧側の `threadId` を維持する。
- `tests/hpb-gmail-sync-auth.test.mjs`
  - 一覧側でスレッドIDが欠けた古いメールと、同一スレッドの新しい取得失敗が混在しても書き込まない回帰テストを追加する。

DB migration、RLS、認証設定、環境変数、実顧客へのLINE・メール送信は変更しない。

## 受入条件

1. 一覧にスレッドIDがなくても、本文取得結果のIDで同一スレッドを判定する。
2. 同一スレッドに取得失敗がある場合、読めた古いメールも保留し同期件数0になる。
3. 別スレッドの成功メールを継続する既存動作を維持する。
4. スレッドIDをどちらからも取得できない失敗では、前工程の全体保留を維持する。
