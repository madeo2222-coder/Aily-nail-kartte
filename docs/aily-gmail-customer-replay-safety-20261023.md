# Gmail外部予約の顧客上書き防止（2026-10-23）

## 利用者に変わること

HPB／minimo の同じ予約について、日時やメニューが変わったメールを再処理しても、初回同期後にスタッフが顧客画面で修正した氏名・電話番号・カナ・メモなどをメール内容で上書きしない。

予約番号から決まる既存の外部予約顧客を先に確認し、同じサロンの顧客ならそのまま再利用して予約だけを更新する。別サロンの顧客が同じ識別子で見つかった場合は、誤更新を避けて書込み前に停止する。

## 対象範囲

- HPB／minimo の予約メールから自動作成した顧客
- 同じ外部予約番号の変更メール再処理
- 顧客の同時作成が競合した場合の収束

新規の外部予約顧客は、従来と同じ決定的IDで追加する。ただし既存行を更新し得る `upsert` は使わず、重複時は先に作成された同一サロンの顧客を読み直して再利用する。

## 受入条件

1. 変更メールの再処理で、スタッフが修正した顧客情報を書き換えない。
2. 新規予約では顧客を1件追加し、その顧客IDで予約を保存する。
3. 同時作成の重複では、先に保存された顧客を上書きせず予約を収束させる。
4. 同じ識別子の顧客が別サロンに属する場合は、顧客・予約とも書き込まない。
5. 既存の手入力顧客照合、予約更新、二重予約・並行更新保護を維持する。

## 変更しない範囲

- DB schema／migration／RLS／権限／環境変数
- Gmail認証・cron設定
- 実Gmail取込、実DB書込み、実顧客通知
- main／本番環境
