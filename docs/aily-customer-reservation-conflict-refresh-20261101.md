# 顧客予約の競合後自動再読込（2026-11-01）

## 利用者が新しくできること

- 顧客が古い予約画面から変更・取消・店舗への希望送信を行った場合、書込みを止めるだけでなく、最新の予約内容を同じ画面へ自動反映する。
- 最新内容を確認したあと、画面を閉じたり手動更新したりせずに、改めて操作できる。
- 空き枠の変化など、入力を残して別の候補を選ぶ必要がある競合では、入力内容を維持する。

## 変更範囲

- 顧客予約APIが、予約改訂値の不一致と予約書込み中の状態競合に `stale_reservation` を返す。
- 顧客予約詳細画面は、この競合だけを判別して予約・ログイン状態・スタッフ一覧を再取得する。
- 再取得に成功した場合は日時、メニュー、担当、備考、操作可否を最新内容へ更新し、確認案内を表示する。
- DB、migration、認証方式、環境変数、LINEの送信条件は変更していない。

## 受入条件

- 古い予約内容による操作は、予約書込みとLINE通知を行わず、最新内容を画面へ反映する。
- 予約の同時更新をRPCが検出した場合も同じ動作になる。
- 空き枠不足など別種の409では、自動再読込せず利用者の入力を残す。
- 最新情報の再取得に失敗した場合は、古い表示を最新と誤認させず再読込案内を維持する。
