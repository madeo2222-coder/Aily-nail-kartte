# 予約メール同期中の担当・メニュー変更保護（2026-10-23）

## 利用者に変わること

HPB／minimo の予約メール同期とスタッフの予約編集が重なった場合、同期処理がスタッフの担当者変更やメニュー変更を古い内容で上書きしないようにした。

同期開始後に担当スタッフまたはメニューが変わっていれば、同期は成功扱いにせず停止する。画面に表示された案内に従って最新内容を確認してから再試行する。

## 対象範囲

- 既存の外部予約を更新する経路
- 同じ予約メールが同時処理され、決定的 ID の INSERT 競合後に既存行へ収束する経路
- 既存の予約状態、スタッフメモ、日時、顧客紐付けの同時変更保護は維持
- キャンセル済み予約を再有効化しない既存の収束処理は維持

## 実装

予約の読取結果へ `menu` を追加し、更新条件に読取時点の `staff_id` と `menu` を含めた。条件に一致する行がない場合は最新行を読み直し、担当スタッフまたはメニューの変更を識別して安全に停止する。

## 検証

- 担当スタッフが同期中に変わった場合に更新を停止するテスト
- メニューが同期中に変わった場合に更新を停止するテスト
- 通常更新および INSERT 競合後の更新条件に担当スタッフ・メニューが含まれること
- 関連回帰、全回帰、型検査、lint、ローカル production build

## 未検証・変更していない範囲

- Aily 実 DB 上での同時更新
- 実 Gmail 取込、実顧客への通知送信
- Supabase migration、RLS、環境変数
- main、本番環境

本変更はアプリ側の比較更新を強化するもので、DB schema の変更は不要。
