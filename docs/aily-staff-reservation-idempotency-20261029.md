# スタッフ予約登録の応答喪失時の重複防止（2026-10-29）

## 利用者が新しくできること

スタッフの新規予約登録で通信切断や応答喪失が起きた後、画面を開き直して同じ内容を再送しても、最初に保存された予約へ収束する。結果不明時に同じ予約が二重登録される経路を防ぐ。

## 修正範囲

- 登録内容に対応する操作IDをブラウザへ保存し、結果不明のまま画面を開き直した場合も同じIDを再利用する。
- 登録成功または明示的な失敗を受け取った場合は保存した操作IDを破棄する。
- APIは操作IDを予約IDとして使用し、同じ内容の予約がすでに存在する場合は既存予約IDを成功として返す。
- 別端末や並行要求が先に同じ予約を作成した場合も、登録後の再確認で同じ内容なら既存予約へ収束する。
- 同じ操作IDで内容が一致しない場合、無効な操作ID、既存予約の確認失敗は安全側で停止する。
- 操作IDを送らない既存クライアントとの互換性、所属確認、過去時刻拒否、予約・外部予定の重複確認を維持する。

## 受入条件

- 応答本文または通信結果を失った送信では操作IDが残り、画面を開き直した同内容の再送で再利用される。
- 完全一致する既存予約への再送は追加登録せず、その予約IDを返す。
- 同時登録競合で片方が先に保存されても、後続要求は既存予約へ収束する。
- 登録成功またはAPIが明示した失敗では操作IDが残らない。
- 内容を変更した次の登録には新しい操作IDを使用する。
