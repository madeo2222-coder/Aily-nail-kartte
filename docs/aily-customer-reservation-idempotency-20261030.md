# 顧客アプリ予約申請の再送・重複防止（2026-10-30）

## 対象業務

顧客アプリから予約希望を送信した際、通信切断や応答喪失後の再読み込みで同じ予約が重複登録されないようにする。

## 実装内容

- 予約内容ごとの操作IDをブラウザに保存し、結果が不明な間は同じIDを再利用する。
- 5xxやJSON欠落を成功・失敗と断定せず、画面上で再送を止めて予約一覧確認へ案内する。
- 新RPCは操作IDの再送、同じ顧客・同じ内容の再送、別スタッフを選び直した同時間帯の重複を原子的に判定する。
- 同じ申請の再送は既存予約へ収束し、メール・LINE通知を重ねて送らない。
- 新RPCが未適用のDBでは既存RPCへ戻るため、現在の予約申請経路は維持する。

## 受入条件

1. 同じ予約内容を応答喪失後に再送しても予約は1件だけになる。
2. 同じ操作IDで内容を変更した要求は409で拒否される。
3. 同じ顧客が別スタッフを選んでも重なる時間帯へ二重登録されない。
4. 新RPCを未適用の環境では従来の予約作成が継続する。
5. 新RPCはservice_roleだけが実行できる。
