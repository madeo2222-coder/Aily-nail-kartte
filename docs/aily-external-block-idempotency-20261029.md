# 外部予約ブロックの再読込後の重複防止（2026-10-29）

## 利用者が新しくできること

HPB・ミニモ・電話などの外部予約ブロック登録で、通信切断や応答喪失の後に画面を開き直して同じ内容を再送しても、最初に保存されたブロックへ収束する。予約カレンダーを重複ブロックで塞ぐ経路を防ぐ。

## 変更範囲

- 登録内容からブラウザ保存用の指紋を作り、同じ内容の再送では同じUUID操作IDを使う。
- APIは操作IDをブロックIDとして保存し、同じID・同じ内容の再送を成功扱いで返す。
- 同時送信で片方のINSERTだけが成功した場合も、保存済み内容を再読取して同じブロックへ収束する。
- 同じ操作IDを異なる内容へ使う要求は拒否する。
- 明示的な入力・競合エラーでは操作IDを破棄し、修正後の再試行を可能にする。通信結果が不明な場合だけ操作IDを保持する。

スタッフ認証、サロン所属、担当者確認、予約・外部予定の時間重複判定、既存の同一画面内の連打防止は維持した。DB migration、env/secret、実データ、実LINE・メール送信は変更していない。

## 受入条件

1. 通信結果不明後は同じ画面で再送できず、予約カレンダー確認へ案内される。
2. ページ再読込後に同じ内容を送ると同じ操作IDを再利用する。
3. 同じ操作ID・同じ内容が保存済みなら新しい行を追加せず成功する。
4. 競合INSERTの後でも保存済み内容が一致すれば成功へ収束する。
5. 操作IDの不正形式や異なる内容への再利用を拒否する。

自動検証は架空データとモックDBで行う。Aily実DBへのUUID指定登録、認証済み実画面での応答喪失・再送、複数端末の同時登録、本番反映は未実施。
