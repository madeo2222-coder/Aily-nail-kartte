# 予約確定LINEの再読込後の再送防止（2026-10-21）

## 利用者が新しくできること

- 予約一覧または予約編集画面で、予約確定LINEが送信済み、または送信結果の確認が必要になった後に画面を再読み込みしても、同じ予約の再送ボタンが復活しない。
- 送信済みの場合は送信済み表示、結果不明の場合は履歴確認の案内を再表示する。
- サーバーが再試行可能と記録した失敗では従来どおり再送できる。

## 実装範囲

- 予約IDごとの再送停止状態を、バージョン付きのブラウザ保存領域へ23時間だけ保存する。
- 保存するのは `sent` / `history_check` の区分と保存時刻だけで、顧客情報、LINE本文、サーバー応答文は保存しない。
- 保存領域が利用できないブラウザでは現在画面のメモリ上の停止状態を維持し、既存動作を壊さない。
- 不正形式・未来時刻・期限切れの保存値は破棄する。

## 確認済み

- 画面再読込相当の再生成で再送停止状態が復元されること。
- 再試行可能結果では保存状態が消えること。
- 23時間経過、不正JSON、保存領域の例外で安全に退行すること。
- 予約一覧と予約編集の両方が同じ保存処理を使うこと。
- 関連テスト37件、型検査、変更ファイルのlint、差分検査。

## 未検証・変更していないもの

- 実顧客LINEは送信していない。
- Aily本番DB、migration、RLS、認証、環境変数は変更していない。
- ブラウザ保存は補助的な誤操作防止であり、サーバー側の送信台帳とLINE再送キーが重複送信防止の最終防衛線である。
- 本成果はローカル検証段階で、統合Previewと本番には未反映。
