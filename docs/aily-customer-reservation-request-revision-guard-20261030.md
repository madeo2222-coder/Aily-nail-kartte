# 顧客予約依頼の内容変更ガード（2026-10-30）

## 利用者が新しくできること

確定済み予約から変更希望またはキャンセル希望を店舗LINEへ送る途中で通信応答を失っても、同じ依頼内容を再読み込み後に再試行できます。再試行前に予約日時、メニュー、担当、店舗、顧客名などが別操作で変わっていた場合は、古い依頼を送信せず最新内容の確認を促します。

## 実装範囲

- 予約詳細APIがLINE依頼に使う予約・顧客情報から改ざん防止用のrevisionを生成する
- ブラウザは依頼文と同じrevisionを23時間の再試行情報へ保存する
- APIは現在のrevisionと一致する場合だけLINE送信へ進む
- revisionがない旧画面、内容が変わった画面、古い再試行情報は409で停止する
- LINE retry keyにも同じrevisionを含め、同じ内容の再試行を同じ送信キーへ収束させる

DB migration、認証方式、env/secret、外部送信設定は変更していません。
