# 顧客予約の認証状態取得失敗を正しく表示する修正（2026-10-28）

## 利用者が新しくできること

顧客がLINE本人認証後の予約詳細を表示・変更するとき、顧客情報の読取に一時的な障害が起きても「LINEログインが必要です」と誤表示されません。再ログインでは解消しない障害をサーバーエラーとして扱い、時間を置いた再試行につなげます。

## 修正内容

- 顧客レコードが存在しない場合だけ未認証として扱う。
- Supabaseの顧客読取が失敗した場合は認証状態を断定せず、500エラーとして安全な一般メッセージを返す。
- 読取失敗時は予約更新RPCやLINE通知を実行しない。
- データベースの内部エラー詳細を応答へ含めない。

## 確認内容

- 顧客読取失敗時の予約詳細取得と予約変更が500になること。
- 「LINEログインが必要です」という誤案内を返さないこと。
- 内部エラー詳細を漏らさないこと。
- 予約更新RPCとLINE通知を呼ばないこと。
- 全回帰テスト、型検査、lint、本番相当fixture build。
