# 別日時提案LINEの再送ロックを予約スナップショットへ連動

## 問題

スタッフが予約確定できない場合に送る別日時入力LINEの再送ロックは、予約行の `updated_at` だけをrevisionとしていた。既存DBで更新日時を自動更新する仕組みが未適用の場合、日時・担当・顧客・メニュー・状態・メモが変わっても古いロックが残り、新しい予約内容に対する案内を止める可能性があった。

## 修正

- 顧客、担当、メニュー、開始・終了日時、状態、メモから決定的なrevisionを生成する。
- revisionには元の顧客IDやメモを保存せず、長さと2つのハッシュだけを使う。
- 上記のどれかが変われば旧ロックを削除し、新しい予約内容として別日時提案を行える。
- 同じ予約内容では送信済み・結果不明ロックを維持し、LINEの重複送信を防ぐ。
- DB migrationや `updated_at` triggerに依存しない。

## 検証範囲

- 同一スナップショットでrevisionが安定すること
- ガード対象7項目の各変更でrevisionが変わること
- 元の顧客ID・メモをrevisionへ含めないこと
- 更新日時が変わらない想定でも、予約内容変更後に旧ロックが破棄されること
- 既存の送信済み・結果不明・期限切れ・legacyロック回帰
- 型検査、lint、全回帰テスト、fixture設定のNext production build

実DB、実スタッフ認証、実LINE送信は未検証。DB・env/secret・本番公開は変更しない。
