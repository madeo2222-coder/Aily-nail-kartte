# 国内ネイルチップ注文の再読み込み復旧（2026-11-03）

## 利用者が新しくできること

- 注文相談の送信応答が途切れても、同じタブを再読み込みして保存結果を確認できる。
- 注文が保存済みなら再送せず、受付完了として表示する。
- 未保存と確認できた場合だけ、送信前に保存した商品・デザイン・サイズ・配送希望を復元して再送できる。
- 保存結果を確認できない間は送信をロックし、「注文結果を再確認」から再照合できる。

## 実装範囲

- 送信前に注文内容とリクエストキーを `sessionStorage` へ保存する。
- 署名済みLINE顧客だけが使える `GET /api/nail-tip-orders?requestKey=...` で、決定的注文IDに対応する保存有無を読む。
- 照合APIは `nail_tip_orders.id` だけを読み、注文内容、顧客情報、他顧客の存在を返さない。
- 保存済み、未保存、判定不能を区別し、判定不能を未保存として扱わない。
- ブラウザ保存が利用できない場合は、結果を追跡できない注文送信を開始しない。
- 再送時は新しいキーや現在の画面内容へ置き換えず、保存済みの同一本文を使用する。

## 確認した受入条件

- 再読み込み後に `saved` を受け取ると、POSTを行わず完了表示へ移る。
- 再読み込み後に `not_found` を受け取ると、入力内容を復元し、利用者の送信操作後に同じ本文だけをPOSTする。
- `unknown` または読取失敗では送信をロックし、二重注文を防ぐ。
- 認証なしの照合は管理接続を開く前に拒否する。
- 照合読取は署名済み顧客ID・店舗ID・決定的注文IDで絞る。
- ブラウザ保存失敗時はPOSTを実行しない。
