# Gmail再取込時の予約状態逆戻り防止（2026-10-21）

## 利用者が新しくできること

HPB／minimoの予約メールがGmail同期で再取得されても、スタッフがすでに「来店」「完了」へ進めた予約は、その状態を保ったまま同期できます。過去メールの再処理で予約が再び確定扱いになり、対応中の一覧へ戻ることを防ぎます。

## 今回の最小納品単位

- 対象: 既存の外部予約番号に一致する予約、または遅延メールと照合された手入力予約
- 保持する状態: `来店`、`来店予定`、`完了待ち`、`完了`、`completed`
- 継続して更新する項目: 日時、メニュー、担当、顧客紐付け、同期メモ
- 従来どおり確定へ収束する状態: `予約` など、スタッフが来店以降へ進めていない状態
- キャンセル済み予約は既存の再有効化防止を維持し、書込み自体を行わない

## 実装と検証

- `lib/reservation-status.ts` にスタッフ進行済み状態の正規化判定を追加
- `lib/hpb-mail-sync.ts` で既存／照合済み予約の進行済み状態だけを保持
- 修正前の再現テストで `来店` が `confirmed` へ戻ることを確認
- HPB／minimo共通同期のテストで、5種類の進行済み状態保持と通常予約の `confirmed` 収束を確認

## 受入条件

1. 外部予約を「来店」または「完了」に変更する
2. 同じ予約番号の元の予約メールを同期対象として再処理する
3. 日時等はメール内容に同期される
4. 予約状態は変更前の「来店」または「完了」のまま再表示される
5. 通常の未進行予約は従来どおり確定扱いになる

## 現時点の区分と残件

コードと自動テストでの確認版です。Aily実DB変更、実顧客メール取得、LINE送信、本番公開は行っていません。次回の単一Previewバッチへ統合後、許可されたテスト予約で状態変更→メール再取込→再表示を確認する必要があります。
