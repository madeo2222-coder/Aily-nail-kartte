# HPB／minimo遅延同期：同時刻帯の手入力予約を顧客で特定

## 利用者ができること

HPB／minimoのメール到着前に複数のお客様の予約を近い時刻へ手入力していても、メールの電話番号から特定した顧客に紐づく予約を選び、同じ予約へ同期できます。担当者が「指名なし」などでスタッフIDを使って絞れない場合も、別行を追加せず既存の手入力予約を更新します。

操作方法は従来どおりです。予約カレンダーの「予約今すぐ同期」を実行します。

## 修正した経路

従来は、同じサロン・開始時刻の前後5分以内に同じ媒体の手入力予約が複数あると、メールの顧客照合より先に候補が複数と判定され、同期を停止していました。

今回、メールの電話番号で顧客を一意に特定してから手入力予約候補を選ぶ順序へ変更しました。

- 顧客が一致する同媒体の予約が1件なら、その予約IDを更新する。
- 顧客未割当の同媒体予約も従来どおり候補にできる。
- 別顧客に紐づく予約だけの場合は、誤更新や重複作成を避けるため同期を停止する。
- 顧客が一致する候補が複数残る場合も、安全のため同期を停止する。
- キャンセル済み、別媒体、外部予約番号が保存済みの予約は再利用しない。

## 受入条件

1. 同じサロン・開始時刻の前後5分以内に、同じ媒体の手入力予約が複数ある。
2. そのうち1件だけが、メールの電話番号から特定される顧客に紐づいている。
3. 同期後、新しい予約を追加せず、その顧客の既存予約IDを更新する。
4. 別顧客の予約内容やメモを変更しない。
5. 顧客が一致する安全な候補がない場合は、予約を追加せずエラーで停止する。

## 検証範囲

- 候補選定の単体テストで、同時刻帯の別顧客候補を除外し、対象顧客の予約を1件に絞ることを確認する。
- 共通メール同期の回帰テストで、対象予約IDへのUPDATE、新規INSERTなし、対象メモの維持、別顧客メモの非混入を確認する。
- 別顧客候補しかない場合の安全停止を維持する。
- DB migration、権限、環境変数、Gmail設定、外部送信は変更しない。
