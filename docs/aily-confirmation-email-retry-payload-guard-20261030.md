# 予約確定メール再試行の内容固定（2026-10-30）

## 利用者に変わること

- 予約確定メールの一時的な送信失敗後に、同じ画面または再読み込み後から安全に再試行できます。
- 最初の試行後に予約日時、メニュー、担当、顧客名、宛先などが変わっていた場合は、古い再試行を送信せず最新内容の確認を案内します。
- 同じ内容の再試行は、最初の試行と同じResend idempotency keyを使います。

## 実装

- 一時失敗時のAPI応答に、送信内容から生成した再試行識別子を含めました。
- 予約一覧と予約編集画面で識別子を24時間の期限とともに保存・復元します。
- 再試行時に現在のメール内容から生成した識別子と一致しない場合、APIは送信前に409を返します。
- 既存の保存データに識別子がない場合も読み込める後方互換を維持しました。
