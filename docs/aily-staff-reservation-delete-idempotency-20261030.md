# スタッフ予約削除の同時操作・再試行収束（2026-10-30）

## 利用者が新しくできること

スタッフが予約を削除する際、別の操作が先に同じ予約を削除していても、削除済みの成功結果へ収束する。通信切断後に状態を確認して同じ削除を再実行した場合も、既に予約が存在しなければ失敗扱いにしない。

## 変更範囲

- 削除開始時に対象予約が既に存在しない場合は、削除済み成功を返す。
- 条件付きDELETEが0件だった場合は予約を再読取する。
- 再読取で予約が存在しなければ、別要求による削除成功として収束する。
- 予約が残っている場合は、同期や別操作で内容が変わった競合として従来どおり409を返す。
- スタッフ認証、サロン所属、HPB・ミニモ予約の直接削除拒否、顧客・担当・日時・状態・メモのスナップショット照合を維持する。

DB migration、env/secret、実データ、実LINE・メール送信は変更しない。

## 受入条件

1. 通常の予約削除は従来どおり成功する。
2. 対象が既に存在しない場合は、書込みを開始せず削除済み成功を返す。
3. 同時削除で先行要求が成功した場合、後続要求も再読取後に削除済み成功へ収束する。
4. 同期や別操作で予約内容が変わり、行が残っている場合は成功とせず競合を返す。
5. 他サロンやHPB・ミニモ予約に対する既存の保護を維持する。
