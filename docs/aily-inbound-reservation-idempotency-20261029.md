# 海外向け予約申請の重複登録・通知防止（2026-10-29）

## 利用者が新しくできること

海外向け予約フォームの送信後に通信が切れたり応答を受け取れなかった場合でも、同じ内容を再送すると最初に作成された予約へ収束する。予約行、店舗通知メール、顧客確認メール、管理者LINEを重複させない。

## 修正範囲

- 店舗、顧客メール、メニュー、人数、開始・終了日時から申請識別値を生成する。
- 申請識別値と人数内の順番から、各予約行のUUIDを固定する。
- 同じUUIDの予約がすべて存在し、店舗・メニュー・日時が一致する場合は既存予約IDを返し、空き枠確認、追加登録、外部通知を繰り返さない。
- 一部の行だけが存在する場合や内容が一致しない場合は409で停止する。
- 別端末の同時申請で固定IDの登録競合が起きても、登録済み行を再確認して同じ申請なら成功へ収束する。
- 店舗通知メールと顧客確認メールには別々のResend冪等キー、管理者LINEには安定したLINE再送キーを付与する。
- 既存のスタッフ空き枠判定、キャンセル済み予約の除外、1〜2名のスタッフ割当は維持する。

## 受入条件

- 同じ申請内容から毎回同じ予約IDと通知キーが生成される。
- 完全な既存申請への再到達は成功として既存IDを返し、DB追加登録と外部通知を行わない。
- 一部一致・内容不一致・既存申請確認失敗では、新規登録と通知を行わない。
- 同時申請の片方が先に登録しても、後続は500のまま残らず既存予約IDを返す。
- 異なる日時、メール、メニュー、人数の申請は別の予約として扱う。

## 検証限界

自動テストは架空データとモック通知で行う。Aily実DBへのUUID指定登録、実Resend、実LINE、実ブラウザ、複数端末からの同時送信は確認しない。DB migration、env/secret、本番データ、実送信は変更しない。
