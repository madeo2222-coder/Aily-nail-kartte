# HPB・minimo 遅延同期の同時実行収束（2026-11-02）

## 利用者ができること

HPB・minimo の同じ予約メールを複数の同期処理が同時に取り込んでも、先に完了した処理が手入力予約へ保存した結果を後続処理が再利用できます。後続処理は同じ予約をもう一度書き換えず、同期失敗として扱いません。

## 変更範囲

- 手入力予約または既存の外部予約を更新する際、楽観的な競合検知で更新に負けた処理は最新行を再読取する。
- 最新行に今回と同じメール本文が保存済みなら、先行同期の完了として収束する。
- 最新行に保存済みのスタッフ追記・状態・顧客・担当・日時・メニューは書き換えない。
- 別のメール、スタッフ変更、キャンセル、別サロンなど既存の安全停止条件は維持する。

DB migration、認証、環境変数、実Gmail・LINE送信、実データ変更はない。

## 受入条件

1. 同じメールを同時同期し、先行処理が手入力予約を更新した場合、後続処理は成功として収束する。
2. 後続処理は追加のUPDATEを実行しない。
3. 先行同期後のスタッフ追記を保持する。
4. 異なる競合変更は従来どおり同期を停止する。
