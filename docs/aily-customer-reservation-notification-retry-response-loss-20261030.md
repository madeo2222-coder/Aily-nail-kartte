# 顧客予約通知リトライの応答喪失継続

## 利用者ができること

予約保存後に店舗通知だけを再試行している途中で通信が切れたり、サーバー応答を読み取れなかったりしても、同じ画面から「店舗への通知を再試行」を続けられる。

## 実装範囲

- 予約保存済みと確認できている通知再試行では、通信拒否、JSON応答喪失、HTTP 5xxを予約保存結果不明として扱わない。
- 予約内容と操作IDを維持し、次の再試行でも同じ予約番号・同じ通知冪等キーを使う。
- 通知成功後は保存済みの再試行情報を削除し、通常の予約受付完了表示へ戻す。
- 最初の予約申請で結果を確認できない場合は、従来どおり二重予約防止のため再送を止め、マイページ確認へ案内する。

## 検証

- 通知失敗後の再試行で、通信拒否、JSON応答喪失、HTTP 5xxの3経路を再現した。
- 各経路で再試行ボタンが残り、3回目の成功時まで同じ本文と操作IDが使われることを確認した。
- 全回帰テスト1152件（成功1150件、失敗0件、任意PGlite 2件スキップ）、全体lint、型検査、実資格情報を使わないfixture設定のNext.js本番webpack buildに成功した。
- 実DB、実LINE、実メールへの送信は行っていない。
