# 海外向け来店予約の再読み込み復旧（2026-11-03）

## 利用者が新しくできること

- 海外向け来店予約の送信応答が途切れても、同じタブを再読み込みして保存結果を確認できる。
- 予約が保存済みなら再送せず、送信完了として表示する。
- 予約が未保存と確認できた場合だけ、ブラウザに保存した同一内容を再送できる。
- 結果を確認できない間は送信ボタンをロックし、重複申請を防ぐ。

## 実装範囲

- 送信直前に、予約内容を `sessionStorage` へ保存する。
- `/api/inbound-reservations` の読取専用 `PUT` に同じ内容を渡し、既存の決定的予約IDで `saved` / `not_found` / `unknown` を判定する。
- 照合処理は予約表の読取だけを行い、空き枠検索、予約書込み、メール・LINE通知を実行しない。
- 通常の `POST` は既存の決定的IDと通知の冪等キーを維持する。
- ブラウザ保存が利用できない場合は、結果を追跡できない送信を開始しない。

## 確認した受入条件

- 通信拒否または成功応答本文の喪失後、同じ画面で二重送信できない。
- 再読み込み後に `saved` を受け取ると、`POST` を行わず完了表示に変わる。
- 再読み込み後に `not_found` を受け取ると、保存済みの同一本文だけを再送する。
- 照合失敗または競合時は `unknown` のまま送信をロックする。
- APIが明確に失敗を返した場合は保存内容を消し、内容を直して再試行できる。
- 既存予約の再送、同時書込みの収束、通知の冪等性を維持する。
