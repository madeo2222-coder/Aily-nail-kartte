# Gmail予約同期：同一スレッド部分取得失敗の安全化（2026-10-22）

## 利用者・目的

HPB／minimoの予約受付・変更・キャンセル通知のうち、一部のGmail本文だけを取得できなかった場合に、読めた古い通知だけが予約内容へ反映されて状態・日時を一時的に戻すことを防ぐ。

## 今回の納品範囲

- Gmail一覧で得られる`threadId`を本文取得結果まで保持する。
- 同じGmailスレッド内に本文取得失敗が1件でもある場合、そのスレッドの読取成功メールもDB同期せず再試行待ちにする。
- 失敗とは別のGmailスレッドは従来どおり同期し、無関係な予約まで止めない。
- APIは保留分を失敗として集計し、全件保留なら`502`、別スレッドの成功を含む場合は`207`を返す。

## 受入条件

1. 同一スレッドの新しい通知取得に失敗したとき、古い通知は`syncHpbMailText`へ渡されない。
2. 別スレッドの正常な通知は同期される。
3. 応答に失敗件数と再試行案内が含まれ、正常終了として扱われない。

## 検証範囲

- 同一スレッド：新しい通知の本文取得失敗＋古い通知の取得成功 → 書込み0件、`502`。
- 別スレッド：一方の本文取得失敗＋独立スレッドの取得成功 → 成功分を維持し、`207`。
- 既存のスタッフ認証、cron認証、受信時刻順、HTML／multipart本文、取得並列数、部分失敗集計を回帰確認する。
