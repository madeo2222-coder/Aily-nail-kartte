# 別日時入力LINEの複数タブ送信防止（2026-11-02）

## 利用者に変わること

スタッフが予約編集画面を複数タブで開き、同じ予約の「別日時をLINEで依頼」をほぼ同時に実行しても、予約内容ごとの送信権を取得した1タブだけが送信APIを呼びます。後から競合したタブは進行中の案内を表示し、顧客への同じ依頼を重ねて開始しません。

## 実装

- 既存の予約内容revisionと5分間のブラウザ保存ロックを使い、送信直前にタブ固有ID付きの所有権を確定する。
- 保存後にロックを読み直し、最後に保存されたIDと一致するタブだけがAPIを呼ぶ。
- `localStorage`が利用できないブラウザでは、画面内の同期ロックを維持して同じ画面からの連打を防ぐ。
- サーバー側の送信台帳、LINE再送キー、予約状態・所属・スナップショット検証は変更しない。

## 確認範囲

- 2タブ競合では片方だけが所有権を得る。
- ブラウザ保存が使えなくても現在画面のロックを維持する。
- 既存の送信済み、結果不明、5分待機、予約内容変更時のロック解除を維持する。
