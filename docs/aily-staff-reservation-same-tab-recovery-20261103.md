# スタッフ予約の同一タブ再読み込み復旧（2026-11-03）

## 利用者が新しくできること

スタッフの手入力予約で通信が切れ、登録結果を確認できないまま同じタブを再読み込みした場合でも、APIが「保存なし」と確認できた後は5分待たずに同じ内容を再登録できる。

別タブで同じ予約を登録中の場合は、従来どおりPOSTを送らず、予約カレンダーで最新状態を確認する案内を表示する。

## 実装範囲

- 予約登録画面の所有者IDをタブ単位の `sessionStorage` に保存する。
- 同一タブの再読み込みでは所有者IDを再利用する。
- 別タブでは別の所有者IDを使い、`localStorage` の5分間の登録中ガードを維持する。
- 登録操作ID、サーバー側の冪等性、結果不明時の再送ロック、保存済み結果の照合動作は変更しない。

## 受入条件

1. 通信喪失後の再読み込みで、APIが `not_found` を返した場合、同一タブから同じ操作IDでPOSTできる。
2. APIが `saved` または `unknown` を返した場合は、従来どおり再送しない。
3. 別タブが有効な登録中所有者を保持している場合はPOSTしない。
4. 正常登録後は予約カレンダーへ移動し、保存済み操作を消去する。

## 検証範囲と限界

自動テストでは、同一タブの所有者ID再利用、未保存確認後のPOST、別タブのPOST拒否、正常完了、結果不明、API失敗を確認する。実DB書込み、実顧客通知、実スタッフ認証での画面操作、Preview反映はこの保存工程では行わない。

DB migration、Supabase設定、env/secret、LINE・メール送信、決済処理の変更はない。
