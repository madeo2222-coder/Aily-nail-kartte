# Gmail本文取得失敗時のスレッド範囲修正（2026-10-24）

## 利用者・目的

スタッフがHPB／minimo予約をGmailから同期する際、1件の外部本文や文字コードの読み取り失敗によって、無関係な予約まで同期停止しないようにする。

## 変更範囲

- Gmail一覧応答に`threadId`がなくても、fullメッセージ応答で判明した`threadId`を保持する。
- fullメッセージ取得後の添付本文取得・文字コード復号等が失敗した場合、判明済みスレッドだけを保留する。
- 同じスレッドの古い予約は従来どおり保留し、状態巻き戻りを防ぐ。
- 無関係なスレッドは同期を継続する。

DB、migration、RLS、認証方式、Gmail設定、外部送信は変更しない。

## 受入条件

1. 一覧にスレッドIDがない予約メールをfull取得する。
2. full応答ではスレッドIDが判明し、その後の外部本文取得が失敗する。
3. 同じスレッドの予約は書き込まず保留する。
4. 別スレッドの読取可能な予約は同期を継続する。
5. APIは部分失敗として返し、再試行対象を残す。

## 検証範囲と限界

- モックGmail応答で、full応答後の添付本文取得失敗、同一スレッド保留、別スレッド継続を検証する。
- 型検査、lint、全回帰、fixture環境のproduction buildを実行する。
- 実Gmail、Aily実DB、実顧客データによる同期は行わない。
- 現行Previewには次の許可済み単一バッチ反映まで含まれない。
