# 予約メール再同期：既存のキャンセルを自動で戻さない

## 原因と最小修正

Gmail同期は過去30日分を再取込する。元の予約メールを再処理した際、予約番号で見つかった既存予約がキャンセル済みでも `status: confirmed` の更新が走っていた。後続のキャンセルメールが取得失敗した場合など、キャンセルを確定へ戻したまま残し得る。実取込コード＋模擬DBで、初回予約→キャンセル→元の予約メール再試行により更新が発生することを再現した。実店舗データでの事故を確認したものではない。

既存予約のキャンセル状態を共通判定で確認し、該当する場合は顧客照合・作成と予約書込みの前に終了する。既存の応答形式 `mode: cancelled, alreadyCancelled: true` と予約IDを返す。これは新たなキャンセル操作ではなく、保存済み状態の維持。既存の同期画面ではキャンセルとして扱う。新しいAPI型・画面・schema・設定・外部送信は追加しない。

同じ外部予約番号のメールだけでキャンセル済み予約を自動再開しない。別の予約番号の通常取込、非キャンセル予約の更新、再試行時メモ保持、顧客不一致拒否、更新結果確認は維持する。
