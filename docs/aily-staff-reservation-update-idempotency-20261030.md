# スタッフ予約更新の応答喪失・同時操作収束（2026-10-30）

## 利用者が新しくできること

スタッフが予約内容を更新した直後に通信が切れ、画面から同じ更新を再実行しても、保存済み内容が今回の希望内容と完全に一致していれば更新済みの成功結果へ収束する。別端末から同じ内容をほぼ同時に保存した場合も、後続要求は再読取で先行要求の成功を確認できる。

## 変更範囲

- 更新開始時の予約が元の画面内容から変わっていても、サロン・顧客・担当・メニュー・日時・状態・メモが今回の希望内容とすべて一致する場合だけ更新済み成功を返す。
- 条件付きUPDATEが0件だった場合は予約を再読取し、同じ希望内容が保存済みなら先行更新成功として収束する。
- 一項目でも希望内容と異なる場合は、同期や別操作による競合として従来どおり409を返す。
- スタッフ認証、サロン所属、HPB・ミニモ予約の直接更新拒否、元データのスナップショット照合、状態遷移、過去日時、重複予約・外部ブロックの保護を維持する。

DB migration、env/secret、実データ、実LINE・メール送信は変更しない。

## 受入条件

1. 通常の予約更新は従来どおり条件付きUPDATEで成功する。
2. 同じ更新が既に保存済みなら、追加書込みをせず更新済み成功を返す。
3. 条件付きUPDATEの直前に同じ内容が別要求で保存された場合、再読取後に更新済み成功へ収束する。
4. 同期や別操作で異なる内容へ変わった場合は成功とせず競合を返す。
5. 他サロンやHPB・ミニモ予約に対する既存の保護を維持する。
