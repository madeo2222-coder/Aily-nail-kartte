# 顧客のLINE希望連絡を文字数上限前に止める修正（2026-10-28）

## 利用者への効果

顧客が予約の変更希望・取消希望へ非常に長い内容を入力した場合、送信できない本文をLINE APIへ送らず、内容を短くして再送するよう画面に案内します。

## 修正内容

- LINEテキストの5000文字上限を、LINEと同じUTF-16コード単位で送信前に確認する。
- 上限超過時は外部送信せず、400応答と再入力可能な状態を返す。
- 顧客操作後の店舗通知でも、上限超過本文をLINE APIへ送らない共通ガードを追加する。
- 既存のLINEリトライキー、重複送信防止、結果不明時の再試行保護は維持する。

## 確認条件

- 5000コード単位を超える完成メッセージではLINE APIを呼ばないこと。
- 顧客へ内容を短くする案内が表示され、入力を修正して再試行できること。
- 通常の変更希望・取消希望は従来どおり送信処理へ進むこと。

## 反映範囲と未検証

自動テストはLINE APIを模した応答だけを使い、実顧客LINEへ送信しません。Aily実DB、実LINE、実機、Preview、本番は未検証・未変更です。DB migration、権限、環境変数の変更はありません。
